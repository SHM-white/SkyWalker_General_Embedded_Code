# chassis_four_modules

与 `gimbal_drive_command` 配套，四轮执行完整低速平移和自转：vx/vy 分别限制 ±0.1m/s，wz 限制 ±0.2rad/s，解算后轮缘速度最多 0.1m/s。接受 Remote 来源的 BodyVelocity/Spin；Spin 按协议忽略平移。只启动 CAN1 舵向和 CAN2 轮驱，不启动大 Yaw，不要求裁判系统和功率模型。

```sh
west build -p always -b dm_mc02/stm32h723xx samples/bringup/chassis_four_modules -d ../build/bringup/chassis_four_modules
west flash -d ../build/bringup/chassis_four_modules
```

云台 USART10（PE3 TX、PE2 RX）与底盘 USART1（PA9 TX、PA10 RX）交叉互接并共地，460800、8N1。遥控接收机留在云台。两板都应重新编译、烧录。本板通过已有 power1 打开电机电源；初始化错误持续输出，不以心跳在线代替电机就绪。

实车四路舵电机均为倒装，共享标定中的舵向 `direction=-1` 同时用于角度/速度反馈和电流输出，使车体俯视逆时针为正。当前电机 ID 1/2/3/4 的原始编码器零点分别为 3060/6517/4431/5145；零点偏移与安装方向分别配置。方向修改后重新编译、烧录底盘。

四个摇杆归中，左 Down 保持至少 500ms → 左 Middle 解锁 → 左 Up 运行。左摇杆控制前后及左右平移；手动档右拨先 Middle 再 Down 请求自转，回 Middle 停止自转。拨轮不参与本阶段。左 Down、遥控过期、授权过期、心跳丢失及 Boot ID 不匹配都会停止；对端断线或重启后重新解锁。急停锁存仍只由真实清除事件解除。

本入口采用仓库已有单轮限流：舵向最多 0.8A、轮驱最多 0.5A，各轮仍受自己的硬件配置限流。原四轮阶段额外的 0.3A 限制移除，避免舵向静摩擦造成始终不能对齐。仍使用共享 ID、零点、减速比和方向，没有把参考固件的参数覆盖进来。运动恢复阈值从 0.02m/s 降到 0.002m/s，停止阈值为 0.001m/s，避免小幅摇杆输入全部落在速度停滞区。零速时舵向保持，非零速时先对齐再开放轮驱；不会绕过四轮反馈与对齐条件。

独立通信线程每 1ms 轮询，控制线程每 2ms 计算并各提交一次 CAN。诊断 UART7/PE8 TX，115200、8N1；共享 `diagnostics_config.hpp` 选择文本/VOFA。首次操作支撑四轮离地，小幅确认前后、横移和自转。未做实板验证。

VOFA 布局仍是 1、19 通道，编号从 0 开始。0=布局；1/2=采样序号低/高16位；3/4=本板时间低/高16位；5=reason；6=当前轮驱测速有效；7=底盘已就绪执行；8=当前轮优化后的轮缘速度÷轮半径（rad/s，包含横移/旋转解算和反转优化，尚未受余弦补偿或对齐门控）；9=当前轮实测 rad/s（无效为 NaN）；10=收到的原命令年龄 ms；11=控制周期 us；12=当前轮驱电流目标 A；13=状态掩码；14=错误码；15/16=诊断丢包数；17=当前轮优化舵角目标 rad；18=舵角反馈 rad（无效为 NaN）。

四轮每 20ms 轮换一次观测，每轮约 80ms 更新一次。CH13 现在编码模块编号与各项门控，用整数按位提取：

| 提取方法 | 含义 |
| --- | --- |
| `value & 3` | 当前轮：0FL、1FR、2RL、3RR |
| `(value >> 2) & 15` | 四个舵向反馈有效位；15=齐全 |
| `(value >> 6) & 15` | 四个轮驱反馈有效位；15=齐全 |
| `(value >> 10) & 15` | 初始化失败位：1=舵向CAN、2=轮驱CAN、4=控制器、8=电源；0=成功 |
| `value & 16384` | 操作授权允许运行 |
| `value & 32768` | 命令绑定本次底盘 Boot ID |
| `value & 65536` | 收到 Remote 来源的 BodyVelocity/Spin 及 Active 命令 |
| `value & 131072` | 命令新鲜 |
| `value & 262144` | 授权帧新鲜且绑定本板 |
| `value & 524288` | 云台心跳在线 |
| `value & 1048576` | 四轮对齐门控已放行轮驱 |

两个反馈掩码中，位1/2/4/8依次代表 FL/FR/RL/RR；例如 11=缺 RL。反馈位独立于运行授权，即使失能也能看到是否收到 CAN 反馈。若两组都为0，先处理电源/CAN；若只有某轮缺失，定位该轮 ID、接线和反馈。

| CH5 reason | 含义 |
| --- | --- |
| 1 | 就绪执行（零速也是有效运行） |
| 2 | 初始化失败；看 CH14 和初始化失败位 |
| 4 | 授权有效但没有手动运行请求 |
| 5 | 等待电机反馈或执行恢复；看两个反馈掩码 |
| 7 | 没有云台心跳 |
| 9 | 授权无效、急停或命令模式/来源/Boot ID 不符合 |
| 10 | 命令过期 |
| 11 | 四轮反馈齐全，正在等待舵向对齐 |
| 12 | 控制周期不符合要求 |
| 13 | CAN提交/传输失败 |

CH8随摇杆变化而CH12为0，不能直接认定命令没收到；reason=11时轮驱正在等舵向。通过 CH17/CH18 比较每轮目标与实际舵角，确认机械零点和方向。需要实际电机响应才能确认现场跑通。
