# 单舵轮双 CAN 遥控台架

默认编译 `src/main.cpp`：GM6020 接 CAN1、ID3；M3508 接 CAN2、ID3。型号、ID、方向和机械参数集中在 `src/board_config.hpp`，启动日志打印实际配置。

上层每个周期更新目标，两轴独立计算和恢复。舵向掉线不阻断轮驱；轮驱掉线不阻断舵向。掉电、CAN 恢复或驱动器故障期间，遥控运行意图保持，设备恢复后自动跟踪最新目标。没有对齐门控、全组就绪屏障或余弦速度缩放。

## 操作和配置

两开关 Down、摇杆和拨轮归中保持 0.5 秒，然后左开关 Middle 启动。左摇杆控制前后和横向目标；单模块没有整车偏航命令。摇杆归中执行既有 Coast 卸力。左 Down/Up 停止，输入超过 100 ms 没有更新也停止。用户停止或急停后，电机再次上电不会自动启动。

电机掉线不用重新解锁。输入失联后的重新解锁属于输入源操作，与电机恢复无关。

| 参数 | 当前配置 |
| --- | --- |
| 舵向 | GM6020 电流模式，CAN1，ID3 |
| 轮驱 | M3508/C620，CAN2，ID3，减速比 3591/187 |
| 电流上限 | 舵向 0.8 A，轮驱 2.0 A |
| 控制周期 | 相对休眠 5 ms，PID 使用实际间隔 |
| CAN | 使用板级位时序，不在应用覆盖 |
| 运动速度比例 | 2.0，运动学上限按同一模块的目标速度范围计算 |
| 等效半径 | `0.01 × (3591/187) ≈ 0.192032 m`，不是实测轮径 |
| 舵向零点 | 2421 ticks；必须与当前机械安装匹配 |

GM6020 必须实际使用受支持的电流模式。零点描述机械安装，不能根据 CAN ID 自动推导。设 `capture_startup_zero=true` 后，首次新鲜绝对角捕获一次临时零点，保留到主控重启；电机恢复不重采。

绝对舵角由模块局部展开，恢复时重建本轴短程计算坐标，不要求多圈参考。轮驱只需要速度反馈。翻转优化、最短转角、转向斜坡、PID 和电流限幅继续生效。

## USB CDC / VOFA

`telemetry-uart` 使用 USB CDC ACM，console 使用板级日志串口。JustFloat 每 10 ms 发 16 通道，发送排队不阻塞控制。遥测不可用或队列满时控制继续。

| 通道 | 内容 |
| ---: | --- |
| 0 | 最新 vx 目标 |
| 1 | 最新 vy 目标 |
| 2 | 优化舵向目标角 rad |
| 3 | 实际绝对舵角 rad |
| 4 | 舵向斜坡参考 rad |
| 5 | 舵向误差 rad，仅用于观测 |
| 6 | 轮驱目标 rad/s |
| 7 | 实际轮速 rad/s |
| 8 | 本周期舵向计算电流 A |
| 9 | 舵向实测电流 A |
| 10 | 本周期轮驱计算电流 A |
| 11 | 轮驱实测电流 A |
| 12 | 遥控 fresh，0/1 |
| 13 | 用户 requested，0/1 |
| 14 | 舵向 output_valid，0/1 |
| 15 | 轮驱 output_valid，0/1 |

缺少反馈时显示 NaN；无本周期计算输出的轴，其命令电流显示 0。每轴有效标志独立，不能由一台电机失联推断另一台没有输出。速度单位沿用参考工程经验比例，实测轮径尚未标定。

## 双电机诊断入口

`-DSWERVE_DUAL_SPEED=ON` 选择 `src/dual_speed.cpp`。6020 在本次用户启动取得的绝对角中心附近正弦往复 ±60°，周期 4 秒；3508 使用独立速度环，默认 4 rad/s。前 0.5 秒目标保持零偏移／零速度。

运行时间轴从用户启动开始，掉线不归零。运行期间舵向中心不重采；下一次用户明确启动才取新中心。若启动时缺少舵向反馈，只有中心捕获等待，轮驱仍按自己的时间轴运行。这个入口只发日志。

```bash
west build -b dm_mc02/stm32h723xx samples/robotics/swerve -d build/swerve_auto
west build -b dm_mc02/stm32h723xx samples/robotics/swerve -d build/swerve_dual_auto -- -DSWERVE_DUAL_SPEED=ON
```

首次调试让轮组悬空，给转向和恢复运动留出空间。电机供电由台架提供，本示例不主动打开 MC02 电机电源口。自动恢复解决控制链阻断，不代表现场 CAN Bus-off 的物理根因已经解决。
