# 单舵轮双 CAN 台架

GM6020 舵向接 CAN1，M3508 轮驱动接 CAN3，两台均为各自总线 ID1。应用创建两个 `CanBus` 和一个跨总线故障组。每 2 ms 运行真实 `SwerveModule`，两条物理 CAN 各提交一次；任一轴或总线失效撤销同组两台电机。

机械参数统一取 `include/robotics/vehicle/calibration.hpp` 的 FL 配置，模块控制参数复用 `include/robotics/vehicle/swerve_profile.hpp`。默认 `connections_confirmed=false`，入口仍保持观测循环，输出禁用。TODO 需要确认电机 ID、电流模式、舵向零点、方向、减速比、轮径、限流和控制参数；悬空确认后才开启确认标志。

恢复过程先撤销旧目标，等新鲜反馈和总线恢复，再把舵向绝对角和驱动当前点作为连续参考，等待两轴各产生新反馈，重置模块与运动学。`RecoveryGate` 拒绝恢复边界之前的输入，且在使能握手期间继续监督命令年龄。暂态故障自动恢复；急停和需要显式清除的故障由 `r` 处理。

控制台：`e` 请求使能；空格禁用；`w/s` 前后、`a/d` 左右、`q/z` 正负旋转、`0` 零速度；`p` 暂停/恢复样例输入生产；`!` 急停；`r` 清除故障并撤销请求。样例只把四轮运动学中的 FL 目标交给真实单模块，完整八电机请使用 `four_swerve`。

先单轴确认方向、轮径换算和共同停机，再验证正反转、跨 ±pi 的翻轮、命令停产、单轴断流、CAN1/CAN3 断流及恢复。日志记录源序号、原始年龄、恢复代次、等待原因、双总线状态和实际机械反馈。

```sh
west build -b dm_mc02 samples/robotics/swerve -d ../build/swerve
```

本轮未执行构建或实板测试；此前旧的单 CAN 构建记录不代表当前双 CAN 配置已验收。

## 参考底盘适配

中央标定已录入参考工程的四轮候选零位 3060/2421/2383/3097、驱动方向 -/+/-/+、减速比 3591/187；仍需核对装配、GM6020 电流模式和几何尺寸，`connections_confirmed` 保持 false。几何沿用待测默认值，不使用参考工程经验性的半径 0.01 m。

控制共享 95°/85°翻转滞回、4 rad/s 舵角目标限速、最终方向误差 0.10/0.40 rad 驱动门控、cos 补偿，以及 0.01/0.02 m/s 低速滞回。四轮版本默认所有非零向量模块对齐后才放行驱动；未对齐时驱动零电流并重置积分/斜坡。零指令默认 Coast（卸力），可在 profile 选择 Hold（保角及零速制动），Disabled 始终撤销。

控制台新增 `u/j` 前进叠加正/负旋转。`e` 从零命令开始使能；运动键只更新目标，不会自动使能。每次使能/运动键续期 1 秒，过期撤销并需重新按 `e`，可按住运动键由终端重复发送。`0` 为零指令卸力。来源暂停仍保留原时间戳；正常运行也不会用不断刷新的内部时间戳掩盖控制台失联。

控制周期采用 2 ms 绝对节拍，迟到跳过错过的时隙，不突发补算。日志使用 deferred logging；四轮遥测每 500 ms 记录限速目标、最终误差、驱动放行、翻转、卸力与电流，避免阻塞电机控制。完整设计见 [舵轮参考移植](../../../docs/dev/舵轮参考移植.md)。
