# 执行骨架实板样例

本样例使用真实 `CommandManager` 服务线程和两个独立的 5 ms 执行线程。合成操作员输入由 `ICommandSource` 提供，仲裁保持 10 ms。底盘和云台分别读取同一个非消耗快照，各自拥有目标、恢复代次、使能握手及生产时间戳。无需电机、CAN、遥控器或 IMU 接线；执行器只更新内存中的模拟目标。

构建和烧录 MC02：

```sh
west build -b dm_mc02/stm32h723xx samples/robotics/execution_skeleton -d build/execution_skeleton
west flash -d build/execution_skeleton
```

Type C 可改用 `rm_typec/stm32f407xx`。日志使用板默认控制台。主机观察入口可使用 `native_sim/native/64`；此入口同样启动真实服务和消费者线程。

## 自动演练

默认每 20 s 重复一轮。时间以系统启动时间为准，故障结束后自动恢复，无需复位。

| 启动时间 / 每轮时间 | 操作 | 预期现象 |
|---|---|---|
| 0–3 s | 正常生产、仲裁和执行 | 两个消费者分别经过准备、等待新输入、20 ms 模拟使能握手后 Active。 |
| 3–4.5 s | 合成输入暂停，返回 `-EAGAIN`；仲裁继续 | manager 序号增长，原始 input 序号不变、年龄增长；100 ms 后两组目标清零。读取和重新仲裁均不能续期旧输入。 |
| 4.5–7 s | 输入恢复 | 两组完成新的独立恢复代次；仅接受准备完成之后生产的新输入。 |
| 7–8.5 s | 云台执行消费者及其状态生产停止；仲裁、遥测继续 | 云台 `status_seq` 停止，`status_age` 增长；100 ms 后 `valid=0`、有效 `ready=0`。底盘持续更新。云台恢复运行时先撤销旧内存目标、报告 Cycle，再重新准备。 |
| 11–11.15 s | 底盘控制线程停顿超过 25 ms | 恢复后的首周期记录 Cycle、目标清零、overruns 增长；重新准备并等待新输入。云台不受该故障影响。 |
| 14–15 s | 云台参考条件无效 | 仅云台撤销目标并等待 Reference；底盘保持运行。参考恢复后只云台增加恢复代次。 |

遥测每 250 ms 输出生产序号、年龄、最终目标、RunState、等待原因、错误、独立 generation、最近控制间隔和超限计数。短时 Cycle 状态可能发生在两个日志采样之间，可通过 `overruns` 及 generation 变化观察。`ready` 日志是经过状态年龄约束的有效就绪；`state` 保留原始缓存值，便于观察旧 Active 如何被状态过期约束拒绝。

关闭自动故障演练可构建持续正常运行变体：

```sh
west build -b dm_mc02/stm32h723xx samples/robotics/execution_skeleton -d build/execution_skeleton_steady -- -DCONFIG_EXECUTION_SKELETON_AUTORUN=n
```

## 恢复契约

`RecoveryGate` 不写电机，由执行线程负责撤权、清除旧目标、参考准备和控制历史重置。每组先决条件满足并完成准备后调用 `prepared()`，形成新的 generation 和生产时间边界。只有仲裁命令及所选原始输入都未过期，且两者生产时间严格在准备完成之后，才开始使能；输入与边界同一毫秒时需等待下一份输入。使能握手期间继续监督输入年龄、命令模式及其他先决条件，任一条件撤销即清除目标。

`SnapshotCache` 的所有消费者均只复制快照，不清除缓存，不修改 producer stamp。真实硬件样例必须由执行线程生产状态，通信线程检查生产年龄后才允许传播 Ready/Active。心跳不能代替执行状态生产时间。

此样例只验证服务、快照、时间、恢复与故障范围，未使用真实电机反馈、物理使能握手、总线提交或机械参考。云台执行停止期间保留的内存目标用于观察陈旧快照，不能作为硬件失效时的独立停输出保障；真实驱动仍需总线与电机层停输出机制。
