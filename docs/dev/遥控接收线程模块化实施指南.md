# 遥控接收线程模块化实施指南

## 实施状态

遥控接收已封装为 `skywalker::communication::RemoteReceiver`，三个 sample 和云台 application 已完成迁移。本文记录当前实现和后续接入方式；完整参数、返回值与可复制入口示例见 [通信层文档](../13-communication.md)。

| 入口 | 迁移结果 | 业务周期 |
| --- | --- | --- |
| `samples/communication/dr16` | 移除 remoteTask 和 BenchSnapshot，VOFA 读取模块 Snapshot；保留 deadband=0 | VOFA 100 ms |
| `samples/robotics/command_safety` | 主循环移除 UART 接收和解析，改读模块快照 | 命令/安全 10 ms |
| `samples/robotics/gimbal_control` | 移除 remoteTask、remote_state，保留双轴 Axis、Group 和急停/重新使能策略 | 云台 5 ms |
| `applications/sentry_gimbal` | 移除 remoteTask、remote_thread、remote_state；main 启动接收模块，commandTask 读快照 | 命令 10 ms，云台 5 ms |

四个入口均已通过 `dm_mc02/stm32h723xx` 编译和链接。未刷写验证，未测线程栈余量；C 板上的新模块构建和运行未在本次验证范围内。

## 数据流与职责

```text
UART 回调 → AsyncUart 字节队列
                   ↓
RemoteReceiver 内部线程：service/read → RemoteService 组帧与解码
                   ↓ Latest<Snapshot>
控制/遥测线程：receiver.snapshot → 重新判断接收超时
                   ↓
mapper / safety / Axis / VOFA 等调用方逻辑
```

每个实例内部只有一个接收线程，默认优先级 6、栈 3072 字节。每轮最多读取 8 个 chunk，休眠 1 ms。读取发生 `-EOVERFLOW` 时调用 discardPartial；解析使用原始 chunk 时间戳。RemoteService 本身仍是单线程解析服务，不对外暴露其可变引用。

拨杆含义、归一化、急停、运动使能和电机反馈判断由 sample/application 决定。裁判和板间通信继续使用各自的 AsyncUart 与解析器。

## 文件与接口

| 文件 | 职责 |
| --- | --- |
| [remote_receiver.hpp](../../include/communication/remote/remote_receiver.hpp) | Config、State、Snapshot、start/snapshot 声明及对象生命周期约定 |
| [remote_receiver.cpp](../../lib/communication/remote_receiver.cpp) | 配置校验、线程创建、接收、状态发布与读取时超时检查 |
| [lib/Kconfig](../../lib/Kconfig) | 模块开关及线程栈、优先级配置 |
| [通信 CMake](../../lib/communication/CMakeLists.txt) | 按 SKYWALKER_REMOTE_RECEIVER 加入实现 |
| [公共 latest.hpp](../../include/latest.hpp) | 非阻塞互斥锁保护的值拷贝 |

`RemoteReceiver(const device*, AsyncUart::DmaBuffers&, const Config&)` 保存设备和缓冲区引用，复制 decoder/remote 配置，不执行 I/O。

`start()` 在线程上下文调用：配置非法返回 `-EINVAL`，重复启动返回 `-EALREADY`，返回 0 表示线程已安排启动。UART 初始化在内部线程中完成，结果见 Snapshot.state/uart_error 及 `Remote UART init: ...` 日志。

`snapshot(Snapshot&)` 允许多个消费线程调用，各自保留一个初始化为 `{}` 的输出变量。返回 0 表示已复制，不代表在线；争锁返回 `-EAGAIN`，保留旧副本，但依然按当前时间收紧 online。与底层 RemoteService.snapshot 不同，它不会返回 `-ESTALE`。ISR 不调用这些接口。

状态从默认 NotStarted，经 Starting 进入 Running 或 InitFailed。状态通过非阻塞快照发布，消费者不一定观察到每个中间状态。Running 表示接收循环运行；尚未收到有效帧时 online 仍为 false。InitFailed 每 100 ms 继续发布失败快照，不重复 init；修复后重启。初始化成功之后的 RX 恢复由 AsyncUart.service 管理。

Snapshot 的 rx_chunks 是读取块数，resets 是连续性重置次数，dropped 是队列丢块数，都不是有效帧数。有效帧序号位于 remote.stamp.sequence。

## 接入新应用

1. prj.conf 启用 CPP、SERIAL、SKYWALKER_LIB_COMMUNICATION、SKYWALKER_UART_TRANSPORT、SKYWALKER_REMOTE_DR16 和 SKYWALKER_REMOTE_RECEIVER。
2. 为实例定义独占的静态 `AsyncUart::DmaBuffers dma_buffers __nocache;`，不带初始化器。定义静态 Receiver，将设备、DMA 引用和配置传入。
3. main 调用 start 并检查返回值。业务线程调用 snapshot，不再创建自己的遥控接收循环。
4. 业务先读取快照，再取本轮 now；如命令安全要求更严格，继续用业务 command_timeout_ms 检查原始 stamp。
5. 同一编译单元统一包含公共 `<latest.hpp>`。sentry_gimbal 的本地重复 src/latest.hpp 已删除，CommandRouter 使用公共版本。

UART 必须独占；对象和 DMA 存活整个固件周期，包括初始化失败后。当前不提供 stop/restart，不将整个 Receiver 对象放入 nocache 区域。缓存和 DMA 细节见 [DMA 说明](../16-uart-dma-nocache.md)。

不要用发布/读取时间刷新旧帧 stamp，也不要因为锁竞争重置有效期。例如最后一帧在 1000 ms，超时 100 ms，则 1100 ms 仍新鲜，1101 ms 离线，即使接收线程没有再次发布。

## 构建与验证

仓库根目录执行：

```sh
west build -b dm_mc02/stm32h723xx samples/communication/dr16 -d build/bench_dr16
west build -b dm_mc02/stm32h723xx samples/robotics/command_safety -d build/bench_command_safety
west build -b dm_mc02/stm32h723xx samples/robotics/gimbal_control -d build/bench_gimbal_control
west build -b dm_mc02/stm32h723xx applications/sentry_gimbal -d build/sentry_gimbal
```

先使用无电机的 DR16/command_safety 验证：断电接线并确认共地、板级遥控 UART 与反相通路，再给主控和接收机上电。初始化日志应为 0；有效输入应更新遥控值和帧序号；关闭遥控后超过超时应离线；恢复输入后只接受新有效帧。command_safety 的 !/r/h/f 操作保持原样。

云台需先核实实际连接、方向、零点、机械限位、pitch 支撑及急停措施，再按原 sample/application 的安全流程验证运动。遥控恢复不得绕过既有使能边界。未完成硬件核对前保持 connections_configured=false。

| 现象 | 排查 |
| --- | --- |
| 一直 NotStarted | main 是否调用 start、返回值和线程调度 |
| InitFailed | uart_error、设备就绪、异步驱动、nocache DMA 和串口是否独占 |
| Running 但离线 | 接收机、接线、串口配置、有效帧与超时；Running 不是在线判断 |
| resets/dropped 持续增长 | 接收线程是否及时运行、队列压力和 UART 重启 |
| 旧值一直在线 | 是否绕过模块读取、覆盖原始 stamp 或仅缓存 online |
