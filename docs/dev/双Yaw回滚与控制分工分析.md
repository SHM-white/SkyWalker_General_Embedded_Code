## 为什么会感觉越来越差

下面是源码中能确认的结构问题和由此推导的影响；没有本机实测波形，不能声称已经证明每项对现场退化的贡献。

1. **视觉 yaw 外环算了，但执行时被绕过。** 原正式入口设置 `yaw_trajectory.valid`，`GimbalExecutor` 优先走 `updateTrajectory()`。因此 `InertialGimbalAdapter` 输出的头部误差修正关节速度没有成为该周期实际 yaw 控制入口。外置 IMU 对计划的超前约束不等于直接闭环跟踪完整视觉目标。
2. **视觉参考系混用。** 视觉目标按外置头部 IMU 定义，旧 Pitch 射线变换却把板载载体平面 yaw 当世界 yaw。两个 IMU 独立初始化，不存在代码保证它们的零点相同。本次从外置头部四元数反解 Pitch 前一级姿态，消除这个混用。
3. **慢分量被多次处理。** 分配器内低通（手动 0.10 s、视觉 0.24 s）、大轴计划跟踪、底盘世界整形、驱动速度斜率和电机闭环叠加。每层单独看都有限幅理由，组合后延迟、相位和实际可用速度已不同于旧调参对象。
4. **大小轴的加速度并没有形成清楚的分工。** 回滚前大轴计划与小轴关节预算都设到 20 rad/s²，小轴电机速度参考斜率也为 20 rad/s²。不能仅凭“低通大轴、高通小轴”的命名认为高加速度已留给小轴。
5. **目标、计划和测量混在了约束里。** 世界计划最多超前 0.25 rad，跟踪预算会缩小，关节计划会重置；下游又可能覆盖外环修正。原始视觉帧仍在，并非所有大目标都被永久删除，但其执行途径已多次改变。
6. **底盘航向目标积分语义变化。** 新实现积分的是上一周期下发的关节速度加底盘速度，包含控制修正和执行限制；旧实现积分请求。这样积分器不再是独立的期望航向轨迹，跟踪误差与目标推进互相影响，需要重新论证，不能当作单纯平滑。
7. **正式视觉反馈实际上未启用。** `VisionReceiver` 默认 `feedback_period_us=0`，旧正式入口也没有 `setFeedback()`。接收视觉命令不代表视觉拿到了这块外置 IMU 的四元数。

因此这次先撤回整条新增分配链，而不是继续增加滤波或提高增益。

旧回中参数：`kp=0.5 /s`，最大请求 `0.6 rad/s`，请求斜率 `0.8 rad/s²`，停止死区 `0.05 rad`，进入阈值 `0.075 rad`。小 Yaw 行程由 5770..7340 ticks 给出，总宽约 1.204 rad（69°），中心到端点约 0.602 rad（34.5°）。

所以在当前软件行程内，回中 P 产生的最大请求约 `0.5 × 0.602 = 0.301 rad/s`（17.3°/s），达不到配置的 0.6 rad/s 上限。这里是上游请求的限制，不是大轴瞬时实测速度的硬上限，底盘航向修正仍可能叠加。大角度转向会慢。

即使持续速度仅 0.1 rad/s，理想回中平衡也需要约 0.2 rad（11.5°）相对偏角。死区也允许停止后保留约数度偏差。**不能靠把旧回中增益调大就同时得到零偏角和高频隔离。**

## 视觉数据契约

反馈使用 `headSensorConfig()`：CAN3/imu-can，主动 Quaternion 上报，ID 0x11，slave 1。路径为 CAN 驱动 → `head.snapshot()` → `vision.setFeedback()` → AB 编码。四元数顺序 w/x/y/z，经过驱动安装转换和归一化；当前 `head_sensor_to_body` 为单位四元数，不合成板载 yaw。gyro 来自同一外置设备，保留各自采样时间，并检查新鲜度与时间差。

AB 反馈为 43 字节：AB、mode、q(w/x/y/z)、yaw、yaw_rate、pitch、pitch_rate、弹速、弹量、CRC16。按用户确认，缺少弹速/弹量时写 0，含义是未知；内部 stamp 仍无效。该能力由 `allow_unknown_ballistics` 显式打开，其他调用者维持严格默认值。

接收为 29 字节，目标是同一参考下的绝对 yaw/pitch，单位 rad，及 rad/s、rad/s²。大角度步进时可把速度/加速度填 0并持续发送该目标；控制请求需有效且导航/视觉仲裁已授权。通信接收超时仍撤销，不把单次报文锁存成无限期运动。

Yaw 使用模 2π 的最短角差。+179° 到 -179° 是约 +2°，不会绕 358°；发送 540° 只表达等价朝向，不能表达“额外转一圈”。若以后确需多圈/指定旋转方向，应增加连续角或圈数协议，不能从四元数推断。

Pitch 保留机械限位 2.60..3.40 rad，水平编码器零位暂为 3.00 rad，仍须实测。大 yaw 偏差下先按目标仰角处理，避免目标在身后产生 180° Pitch 指令；有限机械范围内且安装标定正确时，随 yaw 对齐收敛到目标射线。这里的“目标位置”是既有 AB 的角度目标，不新增 XYZ 弹道解算协议。

参考标识仍为本地约定 `{3,1}`，AB 不携带 epoch；外置 IMU 若内部归零且不报告代次变化，软件不能自动识别，需要重新建立视觉世界参考。板间 `0x0404` 继续传板载载体航向，这是大轴稳向的测量，不应改成枪头四元数。

## 下一版建议：由大轴可达运动决定分工

这部分是设计结论，**本次未重新实现新分配器**。

记外置 IMU 测得枪头世界 yaw 为 θh，小轴编码器角为 q，中心 q0，方向 s=±1。近水平 yaw 机构满足：

```text
θcarrier_in_head_frame = θh - s(q - q0)
ωhead = ωcarrier + s ωsmall
```

这把大轴姿态放到头部 IMU 的同一世界参考里，避免对两个独立 IMU 零点作假设。板载载体 gyro 可继续用于实际运动补偿；大幅俯仰/横滚时用完整旋转运动学替代平面加法。

建议一条完整目标轨迹 θd/ωd/αd，只保留一处速度/加速度分配：

1. **大轴优先承担它能做到的轨迹。** 大轴速度、加速度满足能力且无需高频残差时，把目标世界速度直接前馈给大轴，叠加慢回中偏差修正；不要先经过固定低通再跟随。这样理想模型下能让小轴相对角不变。实物存在延迟、摩擦和测量误差，应约定允许偏差，不能保证每周期数学上恒为零。
2. **小轴完成实际剩余运动。** 用外置 IMU 角误差和 `ωd - ωcarrier_measured` 控制小轴，不用“大轴计划速度”冒充已实现速度。参考分配可用 `αsmall_ref = s(αd - αbig_ref)`，但实际闭环必须继续看测量；约束冲突时应降低共同可行轨迹，不能隐藏缺口。
3. **大目标先规划粗转，小目标保留快速误差。** 大阶跃不应让小轴立刻冲到端点等待大轴。大轴规划带速度/加速度约束的大角度轨迹；小轴残差目标限制在中心附近的工作窗口。最终世界目标始终保留，执行参考可以暂时落后。
4. **行程预留优先于理想频率分工。** 以小轴实测偏角、相对速度和制动距离计算剩余行程；偏角大或即将触限时，大轴提前承担粗转/回中。高频不等于任意幅值都能交给小轴；大幅高频需要放慢共同轨迹。
5. **位置、速度、加速度必须一致。** 如采用关节轨迹直送，外置 IMU 的真实误差修正必须合入同一条最终轨迹；如采用速度外环，就不要同时打开另一条会覆盖它的绝对关节轨迹入口。
6. **约束放在正确层。** 大轴世界参考加速度预算用于分工，原生电机侧还必须约束底盘旋转补偿后的关节速度/加速度。两者坐标不同，不能直接删去后者；应把执行饱和状态反馈给分配层，避免串联多个不透明整形器。

后续独立整定顺序：小轴编码器速度/位置环 → 大轴世界速度/航向环（含底盘运动补偿）→ 头部 IMU 外环 → 联合分配。视觉上位机提供小幅扫频、低加速度长轨迹、大步进和反向轨迹时，分别记录目标 θd/ωd/αd、头部实际角/速度、小轴 q/速度、电机电流、大轴世界速度/关节速度及饱和状态。先得到各轴延迟和可达加速度，再填分配阈值。

## 后续修复：启用视觉回传后遥控不能解锁

现场现象：左拨杆 Up 后云台仍橙灯，底盘闪红灯。定位到本次打开视觉 TX 后触发的 `AsyncUart` 中断模式缺陷：`sendIrq()` 打开 TX 中断后在线程中调用 `uart_fifo_fill()`，正常返回时不关闭 TX；IRQ 回调只处理 RX。当前 Zephyr CDC ACM 驱动要求 FIFO 读写在其回调上下文执行，并在 TX 已开启且 FIFO 有空位时持续重新提交 IRQ 工作。它使用优先级 -1 的系统工作队列，可能使控制、遥控、心跳线程饥饿，或者因错误 FIFO 调用上下文触发断言。因此灯态可以停留在解锁前，底盘随后报失联；不是放开遥控或裁判许可就能修复的问题。

修复：发送线程仅复制数据、记录长度/超时并启用 TX；回调负责填 FIFO，完成或错误立即关闭 TX 中断。周期服务只处理发送超时，不再从普通线程读 RX FIFO。发送与回调共享缓冲区由锁保护，忙时返回 `-EAGAIN`，没有忙等。DMA 异步模式保持原路径，100 Hz 外置 IMU 反馈保留。

本次故障修复需要重新构建并烧录云台固件；底盘沿用上一轮回滚后的固件。编译只能确认构建通过，灯态及恢复解锁仍需现场确认。

此次新增云台 I19=110、底盘 I19=109；通道沿用上文，底盘 I47/I48 置 0（旧执行器没有新增的斜率诊断字段）。两块板均需要更新；若仅刷云台，底盘仍会执行旧缓存逻辑。

### 上电慢、抖与大 Yaw 失能：已确认与未确认

载体平面 yaw 的启动条件来自基线本身：先等待至少 1 s，再连续静止采样至少 1 s、至少 800 个样本，gyro 范数必须低于 0.05 rad/s，加速度接近重力。提前推车/开底盘可使静止标定反复重新计时；`heading_fresh=false` 时大轴请求被禁止。底盘平移不以大轴使能或载体 IMU 标定完成作为前置条件，因此“底盘在动但大 Yaw 失能”在该版本确实可能出现，不能由这个现象直接认定大轴电机损坏。

轮组使用实际舵向误差的 cos³ 补偿，未对准时驱动速度下降。例如**轮组自身舵向误差**为 60° 时，比例为 0.125；这里不能把“枪头相对前进方向偏 60°”直接当成轮组误差。上电初次转舵会慢一些，但持续抖动还需区分目标方向变化、反馈间断、命令时效或舵向闭环，当前无实机波形，未将其中任何一项认定为根因。

今天的舵轮算法/参数对比只见格式变化；明确保留的新增行为有裁判有效拒绝时清零行走命令、键鼠合并、变速小陀螺和通信资源调整。缺少裁判数据不会锁死输出。此前 USB TX 缺陷可以阻塞遥控与板间更新，其修复必须包含在此次烧录文件中。

约 60° 的固定方向偏差尚未定位。软件展开计数重启丢失仍是潜在问题，但单个 25 rad 协议跨度对应约 7.6°；不能无测量证据就把 60° 归因于跨界计数，也不能通过改 `-2.62` 掩盖它。该隐患已包含在选定基线中，回滚不会凭空恢复丢失的跨界历史。

定位所需的最少现场信息：静止上电约 3 s 后云台 I20/I22（载体原因/有效），底盘 I20/I21（大轴门控/执行原因），及大 Yaw 指向同一机械前方时的 I30/I31/I32（原始角/展开角/跨界计数）。先区分“等待标定”与“固定方向偏置”，再决定是否需要独立的机械零位重建方案。此轮不新增未标定的方向补偿或启动运动策略。
