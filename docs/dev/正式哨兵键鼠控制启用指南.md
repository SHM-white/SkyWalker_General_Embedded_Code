# 正式哨兵键鼠控制启用指南

## 目标与前提

假设目标是 `applications/sentry_gimbal` 和既有双板底盘：左 Up 为手动，右 Up 选键鼠，右 Middle 选遥控摇杆，右 Down 请求小陀螺；左 Middle 仍为导航，左 Down 停止。此方案启用 W/S、A/D 平移和鼠标瞄准，不启用发射。实际目标程序、物理拨杆方向及接收机输出单位尚需现场确认；用户提供的快照未能读取。

数据路径：DR16 → `RemoteReceiver` → `RemoteSource` → `ManualCommandMapper` → `CommandManager` 仲裁 → 云台执行器 / 板间底盘命令。`RcControlAdapter` 独立负责新鲜度、解锁和运行授权，裁判许可和板间链路仍是必要约束。键鼠模式下不经遥控摇杆控制平移或瞄准；遥控器拨轮和右 Down 保持原小陀螺职责。

## 按顺序修改

### 1. 仅为正式云台入口选择键鼠映射

在 `applications/sentry_gimbal/src/main.cpp` 的 `CommandManager commands` 配置 lambda 内，`auto config = installed::manualCommandConfig();` 之后加入：

```cpp
config.mapper.input_profile = RemoteInputProfile::KeyboardMouseSelectable;
```

该配置由 `lib/robotics/command.cpp` 的 `ManualCommandMapper::map` 使用：右 Up 选 `ControlSource::KeyboardMouse`，否则选 `Remote`；左 Down 仍为 Safe，左 Up 为 Manual，左 Middle 在导航可用时为 Navigation。不要修改共享的 `gimbalCommandConfig()`，否则会改变其他应用；也不要直接使用 `ShooterSelectable`，它将左 Middle 解释为手动档，与正式应用的导航约定冲突。`RcControlAdapter` 默认的 `keyboard_mouse_selectable` 针对台架的右 Middle 发射模式，本方案无需打开。

映射当前使用 W/S → ±vx、A/D → ±vy，鼠标 X/Y 分别带负号映射 yaw/pitch；`mouse_yaw_scale` 和 `mouse_pitch_scale` 默认都是 0.002，先乘原始量并限制到 [-1, 1]，再乘正式应用对应的最大云台角速度。它们不是台架的 `mouse_*_rate_per_unit`。输出方向和灵敏度必须低速现场标定。鼠标滚轮、其余键、鼠标按键目前没有正式应用动作；不要宣称已启用发射。

### 2. 防止切换来源时执行旧快照

`commands.snapshot(frame)` 由另一个线程更新，切换右拨杆时可能短暂读到前一个来源的帧。修改同一入口，在取得 `frame` 后计算期望的手动来源：

```cpp
const auto expected_manual_source = operator_state.remote.right_switch == RcSwitch::Up
                                        ? ControlSource::KeyboardMouse
                                        : ControlSource::Remote;
```

在构造 `input.command` 并计算 `gimbal_mode_matches` 后、双 Yaw 分配之前，加入运行与手动来源一致性判断；导航模式的视觉来源不作此判断，并移除原先位于分配之后的旧禁用判断：

```cpp
if (!gimbal_allowed || !gimbal_mode_matches ||
    (operator_state.run_allowed && input.command.source != expected_manual_source))
    input.command.mode = GimbalMode::Disabled;
```

在板间发送处，把现有 `manual_command` 定义改为要求来源精确匹配：

```cpp
const bool manual_command = operator_state.run_allowed &&
                            wheel_command.source == expected_manual_source;
```

保留原有 `navigation_command`、禁用分支、裁判许可检查及小陀螺输出覆盖逻辑。切换时旧来源命令被禁用，等待新来源的命令快照；不要修改源时间戳或手工刷新有效期。此处不新增接口、线程或错误码：原来的离线、权限、执行器及板间错误路径继续生效。

### 3. 编译和现场确认

完成修改后，在仓库根目录由操作者执行一次编译：

```sh
west build -p always -b dm_mc02/stm32h723xx applications/sentry_gimbal -d ../build/applications/sentry_gimbal
```

先断开电机动力、卸弹并固定机构，确认构建产物及运行的是本次固件；检查遥控在线、新序号和裁判许可。接通动力前，确认左 Down 停止、拨杆和摇杆归中及现有解锁条件；再按低速、小幅、单轴顺序由现场人员确认：右 Middle 摇杆控制、右 Up 鼠标瞄准和 W/A/S/D 平移、松开后停止，以及两种来源切换时不沿用旧命令。右 Down 的小陀螺、左 Middle 导航、遥控失联和板间断连撤权也应按现场规程确认。编译通过本身不证明方向、限位或电机行为正确。

无动作时先区分遥控是否在线、是否进入手动并解锁、右拨杆物理位置是否对应 Up、裁判许可和板间是否在线；再检查命令来源、模式及诊断原因。方向反了先检查机构方向配置和坐标约定，勿盲目调整多个符号。若鼠标反应过快或过慢，按现场确认的输入单位调整 `mouse_yaw_scale` / `mouse_pitch_scale`，同时保留速度和机械限位。
