# M2006 拨弹盘连续位置目标与卡弹恢复

实现状态（2026-10-04）：用户已禁用本次任务的古法编程模式，下述连续目标与卡弹恢复已写入样例源码；参数仍需实机标定。本文保留实现步骤供调参参考。范围仅为 `samples/motor/m2006_position_control/src/main.cpp` 的调试逻辑，不接入整车发射控制。按先完整实现、最后一次编译的顺序操作，不新增测试代码。

## 1. 当前实现与目标

当前示例每 5 秒切换到 0、90、180、270 度，然后回零。电机为 CAN1 上的 M2006 ID 1，减速比 36，驱动命令电流上限 10 A，位置控制环实际输出上限仍为 0.8 A。

改为连续目标：`target += direction * speed_rad_s * dt_s`。目标不对 `2π` 取模，不按固定时间归零。位置环仍负责追踪这个目标，生成速度参考，再通过速度环生成电流。

每发角度采用**电机减速器输出轴**弧度，和驱动反馈保持同一单位。`rad_per_round` 表示推进一个弹位需要转过多少弧度，`rounds_per_second` 表示期望推进频率：

```cpp
speed_rad_s = rad_per_round * rounds_per_second;
```

两者共同决定固定目标速度，不再另外设置一个可冲突的速度参数。如果希望直接设置速度，则由 `rounds_per_second = speed_rad_s / rad_per_round` 换算。

假设减速器输出轴直接驱动拨盘。若中间还有传动比 R（输出轴转数/拨盘转数），N 个等间距弹位对应 `rad_per_round = 2π * R / N`。不要再把这里的弧度乘以电机内部 36:1 减速比。N、R、正转方向及卡住时的电流均需实机确定，本文数值只用于初始调试。

## 3. 配置与数据结构

在匿名命名空间内删除 `kTargetHoldMs`，保留 `kPi`，加入以下示例配置。阈值需要测量后调整，不代表已经调通。

```cpp
constexpr double kRadPerRound = 2.0 * kPi / 8.0; // 示例：8 个弹位，直连
constexpr double kRoundsPerSecond = 1.0;
constexpr double kFeedSpeedRadS = kRadPerRound * kRoundsPerSecond;
constexpr double kFeedDirection = 1.0;          // 只允许 +1 或 -1

constexpr double kJamErrorRad = 0.25 * kRadPerRound;
constexpr float kJamSpeedRadS = 0.10f;
constexpr float kJamCurrentA = 0.60f;           // 低于当前 0.8 A 环路限流
constexpr std::int64_t kJamConfirmMs = 300;
constexpr std::int64_t kStartupGraceMs = 500;
constexpr double kMaxLeadRad = kRadPerRound;    // 最大目标超前量

constexpr double kReverseRad = 0.5 * kRadPerRound;
constexpr double kReverseSpeedRadS = 0.5;
constexpr double kReverseToleranceRad = 0.03;
constexpr std::int64_t kReverseSettleMs = 100;
constexpr std::int64_t kReverseTimeoutMs = 2500;
constexpr std::int64_t kTransitionTimeoutMs = 1000;
constexpr unsigned kMaxRecoveryAttempts = 3;

enum class FeedState {
    Forward, Stopping, Enabling, Reverse, FaultLatched
};

struct FeedRuntime {
    FeedState state = FeedState::Forward;
    FeedState resume = FeedState::Forward;
    double target_rad = 0.0;
    double reverse_end_rad = 0.0;
    unsigned recovery_attempts = 0;
    std::int64_t state_since_ms = 0;
    std::int64_t jam_since_ms = -1;
    std::int64_t settled_since_ms = -1;
    std::uint64_t last_feedback_ms = 0;
    std::uint64_t reference_generation = 0;
};
```

静态配置用 `static_assert` 检查：每发角度、两种速度、回退量及时间均为正，方向为 ±1；正转和回退目标速度不超过 `kVelocityAbsMaxRadS`；`0 < kJamCurrentA < kSoftwareCurrentAbsMaxA`；卡住速度阈值低于正转速度；位置容差小于回退量；最大超前量大于卡住误差阈值；回退超时大于 `kReverseRad / kReverseSpeedRadS` 加上到位保持时间。若以后改为运行时参数，还要检查所有浮点数有限，非法参数在使能前返回 `-EINVAL` 或 `-ERANGE`。

## 4. 正转目标和卡住判定

在初次使能成功后，初始化 `state_since_ms = now` 和参考代次。主循环保留 5 ms 周期。`target_rad` 使用 double，调用 `axis.update()` 时不要先转换成 float。

每轮先检查 `dt_s` 有限且在控制环允许的 `[0.001, 0.020]` 秒内。超时直接锁存并停止，不把很长的间隔积分进目标，也不将 dt 静默裁剪后继续运行。

Forward 状态核心代码放在原 `requestedPositionRad(elapsed_ms)` 调用位置：

```cpp
runtime.target_rad += kFeedDirection * kFeedSpeedRadS * double(dt_s);
ret = axis.update(runtime.target_rad, dt_s);
if (ret == 0)
    ret = bus.commit().error;
// ret < 0：走统一故障停止，不进入自动卡住恢复。
const auto data = axis.telemetry();
const auto &fb = data.motor.feedback;
const double lead = kFeedDirection *
                    (runtime.target_rad - data.position_rad);
```

`data.position_rad` 与目标都是当前 reset 建立的相对坐标。`data.target_position_rad` 是控制器内部解析后的驱动坐标，不要将它与相对位置直接相减。

必须确认 `data.valid`、`feedback_fresh`、`position_reference_valid`，以及位置、速度、电流有效位和数值。只用时间戳增加的新反馈更新卡住计时；重复读取旧快照不能充当新证据。反馈失效、参考代次变化或驱动故障直接锁存停机，不归类为机械卡住。

经过 `kStartupGraceMs` 后，同时满足下列条件持续 `kJamConfirmMs` 才判断卡住：

- `lead >= kJamErrorRad`：目标沿推进方向明显领先。
- `abs(fb.velocity_rad_s) <= kJamSpeedRadS`：实际基本不转。
- `abs(fb.current_a) >= kJamCurrentA`：实际负载电流较大。

任一条件消失就把 `jam_since_ms` 设为 -1。首次同时满足时记录 now，此后比较时间差，不用循环次数估算时间。这里用实测电流；不要用命令电流代替反馈电流。

额外处理 `lead >= kMaxLeadRad`：即使电流没达到卡住阈值，也进入同样的受限恢复流程，日志标记为“跟踪落后”。这样保留正常阶段固定斜率，同时阻止故障期间目标无限积累。若 `lead <= -kMaxLeadRad`，表示反馈明显超前，直接停机锁存。低速大负载但尚未堵转的情况可能触发跟踪落后，需根据实测跟踪误差调整阈值。

## 5. 回退与重试状态机

关键接口约束来自 `lib/control/motor_control.cpp`：`axis.reset()` 在 Active/Enabling 状态返回 `-EBUSY`；成功 reset 会清除控制历史，并为 StartupRelative 重新建立当前位置零点。因此不能直接在运行中调用 reset，也不能 reset 后沿用旧目标。

建议新增下列样例私有接口，全部仅由 main 控制线程调用，禁止在 CAN 回调或中断中调用：

```cpp
int requestRecovery(FeedRuntime &runtime, std::int64_t now_ms);
int requestReanchor(FeedRuntime &runtime, FeedState resume,
                    std::int64_t now_ms);
int latchFault(FeedRuntime &runtime, int cause);
```

这些函数可以是捕获 `drive` 的局部 lambda，避免把样例电机对象改为全局。接口语义：

- `requestRecovery`：次数未满则计数加一，调用 `requestReanchor(..., Reverse, now)`；次数已满则 `latchFault(..., -EIO)`。0 表示已发起异步停止，不表示恢复成功。
- `requestReanchor`：调用一次 `drive.disable()`；成功后进入 Stopping，记录后继状态和超时起点。负错误直接交给锁存函数。
- `latchFault`：保存首个 cause，状态设为 FaultLatched，调用 `drive.disable()` 并单独记录停止请求错误；返回原始负 cause。此状态永远不再发送运动目标，不自动 clearFault，不自动 enable。

按以下完整顺序实现主循环分支，使用非阻塞状态机，每轮最多进行一次状态推进：

| 状态 | 本轮操作 | 下一状态 |
| --- | --- | --- |
| Forward | 积分、update、commit，检查新反馈及卡住条件 | 正常保持；卡住调用 requestRecovery |
| Stopping | 不 update、不 commit 旧目标；等待 Disabled、`drive.ready()`、新鲜反馈、低速 | 完成 reset、目标清零和 enable 请求后进入 Enabling |
| Enabling | 等待 active；不把等待时间累计为目标位移 | active 后进入预定 Forward 或 Reverse |
| Reverse | 限速累加反向目标，到终点后保持；继续 update、commit | 实际到位保持完成后 requestReanchor(..., Forward) |
| FaultLatched | 保持失能并报告首个故障 | 人工处理后重启样例 |

Stopping 中 `drive.ready()` 还要结合 `drive.snapshot().state == Disabled`，不能只看 `!active()`；Enabling、Fault 和 Offline 都不是允许 reset 的正常停机状态。到达停止完成条件后：

```text
axis.reset() 成功
target_rad = 0
reverse_end_rad = -direction * reverse_rad
清除 jam_since_ms / settled_since_ms
保存新的 reference_generation
drive.enable() 成功
state = Enabling，记录 now
```

reset 重设的是控制参考，不要调用 `drive.reseedPosition()` 改写驱动位置。每次进入 Stopping/Enabling 都有独立的 `kTransitionTimeoutMs`；超时、CAN 错误或反馈失效直接锁存。停止完成前仍保持主循环运行，让 CanBus 后台完成异步停机。

Reverse 使用以下积分方式，避免越过回退终点：

```cpp
const double distance_left = std::fabs(runtime.reverse_end_rad - runtime.target_rad);
const double step = std::min(kReverseSpeedRadS * double(dt_s), distance_left);
runtime.target_rad -= kFeedDirection * step;
```

使用 `std::min` 时添加 `<algorithm>`。在回退阶段，正转目标完全停止累加。回退目标到达终点，并且新鲜反馈满足 `abs(data.position_rad - reverse_end_rad) <= kReverseToleranceRad`、`abs(velocity) <= kJamSpeedRadS`，持续 `kReverseSettleMs`，才算回退完成。不能仅凭时间或目标已到终点判断成功。

回退超过 `kReverseTimeoutMs` 或再次发生驱动故障，锁存停机，不继续自动反复正反转。回退完成后再次走 Stopping → reset → Enabling → Forward，清掉回退过程的积分和旧正转欠账，从新的实际位置开始生成目标。

`recovery_attempts` 为本次程序运行的总恢复次数，成功一次也不清零。最多三次，第四次正向卡住直接锁存；必须人工处理后重启才重新计数。这避免反复“回退成功、推进失败”形成无限循环。

原主循环的 `if (!drive.active()) return -EHOSTDOWN;` 必须改成仅在 Forward/Reverse 中要求 active，否则主动停机恢复会立刻退出。停止和使能等待期间同样不能调用 `axis.update()`。

## 6. 遥测及弹位含义

VOFA 最多支持 16 个浮点通道。保留原通道 0～13 顺序，通道 0 为当前目标，原预留通道 3 改为实测电流；新增通道 14 为状态（0 正转、1 等待停止、2 等待使能、3 回退、4 锁存），15 为累计恢复次数。停止等待和故障状态使用实时驱动反馈，控制器坐标显示 NaN，避免把旧坐标当成当前值。每发弧度和目标速度直接查看源码顶部常量。

只在状态转换时输出日志，记录原因、目标/实际位置、速度、电流及次数。VOFA 发送失败不应中断本来正常的电机控制，可沿用 `m2006_speed_control` 的限频告警方式。

`rad_per_round` 只定义弹位间距。目标转过一个间距不证明已经出弹；回退、空仓、打滑都会打破这种推断。本样例不输出“实际发射数”。需要计数时，另行接入出弹传感器；用于观察的机械推进量应明确标为估算值。
