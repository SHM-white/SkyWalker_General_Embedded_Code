# 外置 IMU 新固件 RS485 协议不兼容与 NaN 定位指南

> 后续状态：用户已授权直接修改代码，已按新协议实施编解码、轮询、超时重试和发送 DMA 配置。下文保留首次定位时的旧代码现象及手工指南，描述“当前代码/未修改”时指首次诊断时点。实物参数和硬件通信仍需现场确认。

## 结论与依据

当前 `samples/imu/dual_imu` 的 RS485 驱动与新手册描述的固件不兼容。当前主控等待外置模块主动发送 `55 AA` 帧，新固件 RS485 则等待主控发送 `A5` 请求：双方都会等待，外置数据一直无效。即使另行发送请求，当前解析器也不能解析新应答。

依据为仓库内厂家原文，不是根据日志猜测协议：

- [DM-IMU-L1 使用说明书 V1.3](../datasheets/DM-IMU-L1%20六轴惯性测量单元使用说明书%20V1.3%202026-09-22.pdf)：适用固件 **2.0.3.0**；第 12–13 页附录 D 规定 RS485 固定 24 字节、仅请求应答、不主动上报、出厂默认 2 Mbps；附录 E 将 `55 AA` 帧定义为 USB 数据协议。
- 同一手册第 7–8 页：启用温控后，普通测量输出要等待温度进入目标值 ±0.5℃ 并连续保持 10 秒。
- [DM IMU 上位机使用说明书 V1.0](../datasheets/DM%20IMU%20上位机使用说明书%20V1.0%202026-09-24.pdf)：第 13 页说明接口、地址和波特率配置及“应用并保存”。第 7 页的 921600 是电脑连接模块 USB 的设置，不是 RS485 出厂速率。

尚未读取实物版本、保存参数或抓取总线数据。协议不兼容是代码与新文档间的确定差异；实际升级版本是否恰为 2.0.3.0，以及是否同时存在接线、波特率或温控问题，仍需实机确认。

本次只写指南，没有修改业务源码，也没有运行构建、测试或烧录。

## 日志如何对应到 NaN

数据路径为：

```text
USART2 RX → AsyncUart 队列 → DmImuParser → acceptDm → ImuState
                                                     ↓
                                                snapshot()
                                                     ↓
                                   fresh_mask → VOFA 通道 6–11
```

`samples/imu/dual_imu/src/main.cpp` 中，6–8 是外置四元数转换后的欧拉角，9–11 是外置角速度；对应 freshness 位没置位，就明确输出 `quiet_NaN()`。

| 日志 | 具体含义 |
|---|---|
| `quat_seq=0 gyro_seq=0` | 从启动到日志结束，这两个字段从未成功发布；不是曾有数据后来过期 |
| `quat_us=0 gyro_us=0` | 没有有效接收时间 |
| `age_us=18446744073709551615` | `UINT64_MAX`，`ageUs()` 的无效时间标记，不是等待了这么久 |
| `fresh=0` | 外置字段全部不新鲜，触发 NaN 输出 |
| `quality=0` | `Unavailable`；成功接收外置四元数后应为 `Unknown=1`，不必等到板载 EKF 的 `Tracking=3` |
| `state=1 init=0` | 本地接收器运行、UART 初始化成功，不代表 IMU 已响应 |
| `error=0 gaps=0` | 没有被现有路径记录的错误或断流事件，不代表收到过字节 |

`DmImuRs485Source::service()` 只调用 `uart_.service/read`，没有 `uart_.send()`。队列为空时返回 `-EAGAIN`，没有无数据超时错误。解析器遇到非 `55 AA` 的普通字节也可能仅丢弃，因此现有日志不能区分“零字节”和“收到不认识的字节”。

USB 枚举日志和 `VOFA send=-105` 属于主控向电脑输出的链路；它们不能解释外置源自己的序号一直为零。`sensor_to_body requires calibration` 也不是本样例的数据采集门禁。

## 新旧差异及请求示例

| 项目 | 当前代码 | 新手册 RS485 |
|---|---|---|
| 收发方式 | 只接收主动数据 | 主控请求，模块应答 |
| 波特率 | overlay 固定 1,000,000 | 出厂默认 2,000,000，实物可能保存了其他值 |
| 帧头、帧尾 | `55 AA`、`0A` | `A5`、`5A` |
| 帧长 | 19 或 23 | 固定 24 |
| 数据编号 | type 1/2/3/4 | RID 0/1/2/3 |
| float 起始偏移 | 4 | 5 |
| 校验 | CRC16/CCITT-FALSE | 附录 D 无 CRC 字段；偏移 21 是应答码 |
| UART DMA | 只有 RX | 使用现有异步发送接口时还需要 TX DMA |

新协议偏移从 0 开始：

| 偏移 | 内容 |
|---|---|
| 0 | `0xA5` |
| 1 | `0x0D`，读取数据 |
| 2 | 从机地址低 8 位，当前样例期望 1 |
| 3 | RID：0 加速度、1 角速度、2 欧拉角、3 四元数 |
| 4 | 0，读操作 |
| 5–20 | 请求填零；应答放 3 或 4 个小端 float |
| 21 | 应答码，0 成功，非零失败 |
| 22 | 保留，填零 |
| 23 | `0x5A` |

地址 1 的四元数读取请求如下，用分组避免数错零字节：

```text
偏移 00–04：A5 0D 01 03 00
偏移 05–20：00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
偏移 21–23：00 00 5A
```

读取角速度只将偏移 3 改为 `01`。应答四元数从偏移 5、9、13、17 读取 W、X、Y、Z；角速度从 5、9、13 读取 X、Y、Z，单位仍是 rad/s。小端浮点 `00 00 80 3F` 表示 1.0，不能直接当整数值使用，也不要从未对齐的偏移 5 强转 `float*`；复用 `core::wire::f32()`。

## 手工修改顺序

遵循 implementation-first：连续完成以下修改后，再做最后一次编译；不逐个函数循环测试或审查。本节是待实施内容，不是已经应用的补丁。

### 1. 给 RS485 单独增加 24 字节协议编解码

位置：`include/drivers/imu/dm_imu_protocol.hpp` 和 `drivers/imu/dm_imu_protocol.cpp`。

保留现有 `DmImuParser` 的旧帧语义，新建明确命名的 RS485 编解码路径，避免把仍适用于 USB 的 CRC 和 19/23 字节解析静默改成另一种协议。当前旧协议测试也不能证明新 RS485 可用；本任务不新增或运行测试。

建议核心接口（声明示例，需在相应命名空间实现）：

```cpp
struct DmRs485Reply {
    std::uint8_t id{}, rid{}, response_code{};
    Update update{};
};
int encodeDmRs485Read(std::uint8_t id, std::uint8_t rid,
                      std::uint8_t *out, std::size_t capacity);
int decodeDmRs485Reply(const std::uint8_t *frame, std::size_t size,
                       core::TimeUs rx_us, DmRs485Reply &out);
```

- `encode`：空指针、容量不足或 RID 超出 0–3 返回 `-EINVAL`；成功返回 24。先清零 24 字节，再填帧头、类型、ID、RID 和帧尾。不发送校准、归零或配置指令。
- `decode`：成功返回 0；参数错误返回 `-EINVAL`，帧长/头尾/类型/操作/保留字段错误返回 `-EBADMSG`。非零应答码通过 `response_code` 上交，不读取其数据区、不发布测量；设备错误码的具体含义手册未给出，不臆造枚举。
- RID 0/1/3 分别产生 `Accel/Gyro/Orientation` 更新；RID 2 可解析后忽略，不用欧拉角替代四元数。新 RID 3 是四元数，不能照搬旧 `type==3` 为欧拉角的分支。
- 验证浮点有限性，四元数必须可归一化；四元数质量设为 `Unknown`，接收时间传入字段时间戳。序号仍由 `ImuState::publish()` 增加。
- 在新解析器中做流式组帧：24 字节缓存、找到 `A5` 后继续收集、头字段或完整帧无效则滑动一个字节重新同步。处理一次输入包含多帧、跨队列块拼帧和半帧超时。不要假设一次 DMA 回调就是一帧。
- 编解码及组帧仅在接收器所属线程调用；不在 UART 回调里解析、做浮点运算或更新 IMU。

### 2. 将外置源改为非阻塞请求/应答轮询

位置：`include/drivers/imu/dm_imu_rs485.hpp`、`drivers/imu/dm_imu_rs485.cpp`。

保留 `acceptDm()` 中的单位、安装旋转、参考系和 `ImuState` 发布路径；将旧解析器接入替换为上面的 RS485 路径。源对象管理一个未完成请求，不能同时发多个 RID 后猜测应答归属。

```text
service():
  推进 UART 恢复和 TX 状态；读取并处理接收队列
  检查发送结果、应答、超时及重试次数
  空闲且达到计划时间：发送当前 RID 的 24 字节请求
  TX 完成：进入等待应答（也处理发送期间已入队的快速应答）
  匹配 ID/RID、结构正确、应答成功：发布对应字段，再轮到下一 RID
  没有新数据：返回 -EAGAIN，不阻塞接收器线程
```

轮询顺序建议四元数 RID 3 → 角速度 RID 1 → 加速度 RID 0；每次成功后尽快推进，但每次调用只做有界工作。样例每 1 ms 调用一次 `service()`，无需额外创建线程或重复初始化 UART。

发送必须复用 `AsyncUart::send/txBusy/txError`。`send()` 返回 0 只表示提交成功，不代表串口已经发送完成。发送忙时保留当前待发请求；失败时记录错误，不把失败当应答超时。不能提前释放 DMA 缓冲或覆盖忙碌 TX；现有 `send()` 会把请求复制进自己的 DMA 缓冲。

手册建议高负载总线设置 50–100 ms 应答超时、最多重试 2–3 次。可先选 50 ms 和最多 2 次重试；超时记 `-ETIMEDOUT`，重试耗尽后轮到下一 RID。应答超时与半帧组装超时是两个不同计时器。等待上限不是正常轮询间隔，不要每次成功应答后再固定等 50 ms。

非零应答码记为设备应答失败（例如本地 `-EIO`，同时保留原始码），不要更新数据或新鲜度。ID/RID 不匹配的帧不能结束当前请求。队列溢出时丢弃半帧并增加 gap，不得拿残帧拼接发布。

协议没有事务序号，无法彻底区分同一 RID 的迟到应答和重试应答；保留接收时间的含义，不声称这是设备采样时间。请求与应答结构相同，也必须确认实际 RS485 硬件无本地回显；如果会回显，应在传输层利用发送阶段和接收时序排除请求回显，不能只按“数据全零”过滤，因为静止角速度全零完全合法。

建议由同一 owner 线程每秒限频打印：接收字节数、发送请求数、有效应答数、超时数、结构错误数和最后设备应答码。不要让 telemetry 线程无锁读取可变解析器状态，也不要在 ISR 内打印每个字节。

### 3. 配置 TX DMA、实际波特率并更新样例说明

位置：`samples/imu/dual_imu/app.overlay`、`src/board_config.hpp`、`README.md`。

若实物保存速率确认为 2 Mbps，overlay 的 USART2 改为：

```dts
&usart2 {
    current-speed = <2000000>;
    dmas = <&dmamux1 5 43 STM32_DMA_PERIPH_RX>,
           <&dmamux1 7 44 STM32_DMA_PERIPH_TX>;
    dma-names = "rx", "tx";
};
```

当前板级 DMA 使用通道 1/2（SPI2）、3/4（USART1）、6（UART5），样例占用 5 做 USART2 RX，所以这里选择 7 做 TX。HAL 的 `stm32h7xx_hal_dma.h` 定义 USART2 RX request=43、TX request=44；请求号与 DMA 通道号不是同一个概念。该选择针对当前 MC02 样例，若追加 overlay 占用了 7，应另行分配。

板级已经配置 PD4 DE、PD5 TX、PD6 RX 和 `de-enable`，应保留硬件方向控制。实机仍须确认发送结束后 DE 及时释放。若模块实际保存 1 Mbps，双方一致使用 1 Mbps 即可；单独改成 2 Mbps并不能修复协议。

保留地址 1 的前提是实物从机地址低 8 位为 1。加速度和角速度缩放保持 1，新文档给出的单位已是 m/s²、rad/s。保持 freshness 的数据无效语义，不用输出 0 或无限延长 freshness 掩盖掉线。当前 20 ms 有效期要求健康情况下每一类轮询周期都小于 20 ms；若实际更新率较低，要根据用途明确调整。

README 中“RS485 主动模式、四类数据全开、RX only、无需 TX DMA”的旧说明需要替换。仅在厂家软件勾选四元数输出，不能恢复新固件的 RS485 主动模式，因为新协议明确不支持该模式。

## 实物配置、最终编译与现象

先用厂家 USB 软件读取版本、从机地址、RS485 波特率、通信类型及温控状态并记录；保存速率修改后按手册重启。确认不是设置模式或校准进行中。不为定位问题执行恢复出厂设置，以免清除现有校准。

提供的日志只到启动后约 1.47 秒。如果开启了外置模块温控，尚不足以判断它完成了“到温后稳定 10 秒”的条件。这里的外置温控与样例给板载 BMI088 的 `ImuHeater` 是两回事。手册未具体规定门控期间 RS485 返回错误还是不应答，需要抓帧确认；不要将所有超时都直接解释为断线。

完成全部实现后，由用户进行一次编译：

```sh
west build -p always -b dm_mc02/stm32h723xx samples/imu/dual_imu -d build/dual_imu
```

准备进行实机观察时，先断开电机动力，断电确认 485-2 A/B、供电及地连接，接妥后上电，烧录命令为：

```sh
west flash -d build/dual_imu
```

正常情况下请求与应答交替出现，外置 `quat_seq/gyro_seq` 持续增加、`quality=1`，三种字段都新鲜时 `fresh=7`（只收到四元数和角速度时为 6）；VOFA 6–11 恢复有限数值。NaN 保护本身应保留。

若仍无数据，按实际观测区分：没有 TX 请求检查 TX DMA/发送错误；有 TX 无 RX 检查 DE、A/B、地址、速率、供电、温控；有 RX 无有效应答检查 24 字节结构和 ID/RID；序号增长但间歇 NaN 检查每种字段的实际轮询间隔和 20 ms freshness。
