# 鼠标发射手势与单双发控制实施指南

本文件是待实施方案，业务代码尚未修改。输入沿用遥控器/接收机的 DR16/DBUS 键鼠透传。第 8 节补充鼠标瞄准手感的实现与人工调参方法。

## 1. 已确认的操作规则

| 输入                                  | 请求行为                                                         |
| ------------------------------------- | ---------------------------------------------------------------- |
| 按住鼠标右键                          | 开启摩擦轮；是否就绪仍由实际转速和稳定时间决定                   |
| 松开鼠标右键                          | 关闭摩擦轮，撤销供弹请求，清除待处理的点击                       |
| 单次点击左键                          | 请求一发；不等待第二次点击才能决定第一发                         |
| 连续点击左键，相邻按下间隔小于 500 ms | 从第二次点击起自动连发，射频与持续按住完全相同；点击之间保持连发 |
| 持续按住左键                          | 首先请求一发，达到长按门槛后请求自动连发                         |
| 连点模式下停止点击                    | 距最后一次按下达到 500 ms 时退出连发                             |
| 长按模式下松开左键                    | 撤销连发请求                                                     |
| 遥控器模式的发射拨杆                  | 默认请求连发，不再先单发、等待 500 ms 后才连发                   |

不再使用此前建议的 Q 开摩擦、E 切换单/连发，也不采用右键单击锁存开关。

“500 ms 以下的频率”在这里解释为**相邻两次按下左键的间隔严格小于 500 ms**；恰好 500 ms 重新作为一次普通点击。

**快速连点和持续按住都请求同一个 `FireContinuous`，使用同一个 `fire_rate_hz`。点击频率只决定是否进入、维持连发，不决定发射频率，也不限制为一次点击一发。** 此规则替代此前错误的“快速连点每次最多授权一格”解释，不需要有限点击预算。

连点模式必须跨越两次点击之间的左键松开间隙，否则会在每次点击时打断供弹。系统无法在最后一次松开时知道之后还会不会再点，因此使用 500 ms 无新点击作为退出条件：从最后一次按下计时，达到 500 ms 后撤销连发。这是连点结束的判定延迟；在该时间窗内仍按设定射频供弹。若要立即撤销，松开右键。输入失联仍按原有更短超时停机，500 ms 不延长输入有效期。

长按门槛暂取 `hold_to_auto_ms = 250`，独立于 `rapid_click_gap_ms = 500`。250 ms 是建议初值，尚未由操作者或实机确认；达到门槛后不能把首次按下的一发再次补发。

## 3. 数据流与状态归属

```text
DR16 成功解码的原始帧
  → 带原始时间戳的鼠标按键帧
  → 唯一操作管理者：右键门控、左键边沿、点击间隔、长按计时
  → CommandManager 仲裁：来源、运行模式、许可
  → 执行线程：单次事件去重、位置/速度控制选择、机械完成条件
  → 每条物理 CAN 总线每周期统一提交
```

“按下边沿”指上一帧未按、这一帧按下。重复读取同一帧不能再产生边沿，也不能刷新原始时间戳。两次按下之间必须实际收到松开的状态，不能把重复的按住帧计为连点。

持续状态放在长生命周期的操作管理对象中，单线程拥有；不要由仲裁线程和执行线程各自判断一遍。跨线程传递完整快照或有界队列，不共享无保护的可变状态。

输入若只经过 `latest_`，中间的松开/按下可能在调度暂停时被覆盖。为保留已经成功解码的边沿，在 `RemoteService::processBytes()` 每次解码成功之后、覆盖下一帧之前发布鼠标按键帧到有界队列，由唯一操作管理者顺序消费。该路径在接收线程执行，不在 UART 中断里运行操作状态机。读取快照的诊断代码不消费此队列。

队列溢出时撤销发射会话，要求释放左键后重新触发，不根据“现在还按着”猜测丢失的点击。队列只保存有限且新鲜的输入，恢复执行时丢弃过期数据，不重放一串旧点击。接收链路本身未传来的点击无法由 MCU 恢复。

## 4. 手势接口与伪代码

建议新增 `include/robotics/command/mouse_shooter_gesture.hpp`，由命令层长期持有。下面是接口设计，不是已经存在的 API：

```cpp
enum class MouseFeedKind { Idle, ClickSingle, RapidContinuous, HeldContinuous };

struct MouseFireIntent {
    bool friction_requested = false;
    MouseFeedKind kind = MouseFeedKind::Idle;
    std::uint32_t click_event_id = 0;
    MessageStamp click_stamp{};
    MessageStamp source_stamp{};
};

class MouseShooterGesture {
public:
    struct Config {
        std::uint32_t rapid_click_gap_ms = 500;
        std::uint32_t hold_to_auto_ms = 250;
    };
    explicit MouseShooterGesture(Config);
    int update(const RemoteState &, bool keyboard_mouse_selected,
               bool run_allowed, std::uint64_t now_ms, MouseFireIntent &out);
    void withdraw();
};
```

接口约定：

- `now_ms` 是单调时钟，用于判断输入年龄和连点退出期限；点击间隔与长按进入条件使用原始输入帧的 `stamp.timestamp_ms`。
- `update()` 仅由操作管理线程调用，不控制电机。返回 `0` 表示输出完整，`-EINVAL` 表示配置不合法，`-ESTALE` 表示输入过期或时间顺序异常；出错输出必须撤销摩擦/发射。
- 重复帧仍检查失联和连点退出期限，但不重复处理边沿、不据此进入长按连发。新点击与进入长按由新鲜的新帧确定，撤销操作不必等待新帧。
- `withdraw()` 清除连点、长按和待处理事件，设置“必须先释放左键”；不重置全局事件编号。
- RC 与键鼠事件采用同一操作管理者的递增编号，或明确扩展来源会话身份；不要各自从 1 计数后共用执行器的 `last_event_id`。
- `click_stamp` 始终是单发点击的生产戳。后续仲裁刷新命令戳时不能给旧单发续期。连点另外保存最后一次按下时间；两次点击之间的新鲜按键帧可以维持输入在线，但不能刷新这个点击时间。

状态处理顺序如下。`emit_single()` 只为普通首次点击产生单发事件；两种 Continuous 都是持续请求，不制造额外的离散单发事件：

```text
每轮先检查：输入新鲜、已选择键鼠、已解锁
不满足：withdraw，输出 Disabled

收到新帧后：
    若右键松开：
        摩擦请求=false；撤销所有供弹；清空点击历史
        要求左键先松开再按；结束本帧处理

    摩擦请求=true
    若刚进入键鼠或刚重新开启右键，左键已经按着：
        等待左键释放；不把它当成新点击

    若仍要求释放：
        左键松开时解除此要求；本帧不产生发射
        结束本帧处理

    若左键产生按下边沿：
        rapid = 存在同一有效会话内的上次按下
                且 0 <= 当前按下时间 - 上次按下时间 < 500 ms
        若 rapid：
            进入 RapidContinuous；不再给本次点击追加一发
            撤销尚未接受的旧单发事件，避免之后重放
        否则：
            为本次点击分配事件编号及原始时间戳
            emit_single()；进入等待长按的状态
        记录此次按下时间，并更新上次点击时间

    若左键持续按住，且本次按住已达 250 ms：
        进入 HeldContinuous，结束连点保持逻辑
        撤销尚未接受的旧单发事件，不再制造新的单发事件

    若左键松开：
        若此前是 HeldContinuous：
            退出连发，清除点击历史；下次重新从首次点击开始
        若此前是 RapidContinuous：
            保持连发，不因两次点击间的松开中断
        若只是普通短点击：
            保留该单发事件供执行层去重消费，不产生持续请求

顺序处理本轮新鲜输入后，每轮都检查：
    若 RapidContinuous 且 now_ms - 最后一次按下时间 >= 500 ms：
        退出连发并清除点击历史
    若两种 Continuous 任一种有效：
        输出同一个 FireContinuous 和同一个配置射频
```

连续点击中的某一次变成持续按住时，达到长按门槛后转为 HeldContinuous；之后松开左键直接退出，不再继续沿用连点的 500 ms 时间窗。所有退出条件在输出命令之前处理，避免已经过期的连点请求短暂进入执行层。

右键关闭的处理优先于同帧左键点击。首次启动、切换来源、失联恢复、清故障之后，需要先见到左键释放；右键保持按住并不等于重新触发左键。

“点击只生产一次”不等于发布一个可能被执行线程漏读的瞬时布尔量。保留事件编号与原始戳供执行层消费/去重，直到被后续事件替换、明确撤销或过期；必须限制待执行事件，禁止形成恢复后补发的无界队列。

## 5. 拨盘执行合同

沿用之前的位置/速度分工；两种手势进入完全相同的连发执行路径：

| 意图            | 执行方式                                                         | 供弹授权                                                 |
| --------------- | ---------------------------------------------------------------- | -------------------------------------------------------- |
| ClickSingle     | 位置控制到下一分度                                               | 此事件最多一格                                           |
| RapidContinuous | 速度控制，`ω = fire_rate_hz × dial_step_rad`，再应用机构上限 | 右键按住、连点未超时且全部许可有效；左键的点击间隙不打断 |
| HeldContinuous  | 与 RapidContinuous 相同的速度控制、相同射频和限幅                | 左右键同时按住且全部许可有效                             |

直接复用现有 `ShooterMode::FireContinuous` 和 `fire_rate_hz`，无需为快速点击增加“每次一格”的预算字段。手势原因只留在输入状态或诊断中，拨盘执行层不应因手势不同使用不同射频。统一射频取同一配置来源；替换或绕过当前 `RcShooterRequest` 中硬编码射频、重新解释命令的路径，避免两种输入得到不同频率。

普通单发按实际位置误差、速度和稳定时间判断完成，不能用目标生成结束假装到位。未就绪或许可不足时单发可以被拒绝并消费，不积压补发。连发按照配置射频生成供弹请求，每发仍须正确核算热量，而不是按鼠标点击次数核算。

一次单发尚未完成时进入任一种连发，可先完成已接受的一格，再切入速度模式；处理首发与后续连发的时间衔接，避免重复计数或在切换瞬间额外追加一格。切换控制器时处理目标和积分状态，每周期只允许一个控制器给拨盘写输出。

退出连发时速度目标归零并受控减速，不继续追赶无限累积的旧位置目标。以后再次单发，应结合停下后的有效机械相位确定下一分度；刹停和相位处理需实机标定。

连点超时或长按释放时撤销持续请求。右键释放、Safe、失联或故障优先撤销所有发射请求并走停机路径，不等待 500 ms、不为完成一格继续保持发射。软件撤销请求不等于电机在同一瞬间停止。

位置/速度模式切换不解除摩擦就绪、热量、裁判许可、位置参考、输入过期等既有条件。当前空载样例的许可旁路只适用于无弹调试。

## 7. 最终编译与后续人工调参

本指南没有执行以下命令。全部实现完成后，可由操作者进行一次最终编译：

```sh
west build -b dm_mc02/stm32h723xx samples/robotics/gimbal_shared_can -d /tmp/skywalker-gimbal-mouse-build
```

不自动刷写、不执行固件、不新增或运行测试。以下是之后人工上机调参时的操作预期，不是本次已经验证的结果：先保持执行器电源断开确认输入与模式，再在无弹、机构可安全转动的条件下按现有流程接通执行器电源和解锁。

- 按住右键：先启动摩擦，等待实际就绪；松开则关闭并撤销供弹。
- 左键单点：只出现一个事件，不能每个控制周期重复生成。
- 右键始终按住，左键在 0、300、600 ms 分别短点：0 ms 请求单发，300 ms 起请求固定射频连发，600 ms 续期；两次点击间保持连发，1100 ms 起撤销连发，实际处理受线程调度影响。这段时间的发数不限定为三发。
- 同一射频配置、同样的执行许可下，快速连点和长按的稳定连发拨盘目标速度相同，不随点击快慢改变。
- 两次点击间隔恰好 500 ms：第二次重新按普通单击处理。
- 左键按下不松：首次点击一次，达到独立长按门槛后持续请求；松开不再追加。
- 未开右键便按住左键，再开右键：等待左键释放重按，不自动触发。
- 来源切换、失联、队列溢出：不重放旧点击。

若快速点击未进入或维持连发，先观察原始帧是否包含每次松开与按下，再看点击间隔、输入过期和执行许可；不要用每次点击追加一格替代固定射频连发。若停点后仍转动，先区分正常的 500 ms 判停窗口、机械减速、旧位置目标追赶和未撤销的持续请求；超过最后一次点击 500 ms 后，软件不应继续保持连发命令。

## 8. 鼠标手感优化方法

本节目标是：微调能动、相同移动距离对应稳定转角、快速转向不过早饱和、停止和反向时拖尾可控。机械云台存在惯量、行程和通信延迟，需要分别处理输入映射与机构响应。本节给出的是后续实现和人工调参方法，尚未在当前硬件上验证。

**鼠标移动与鼠标按键分开处理。** 右键仍只负责按住开启摩擦轮，不叠加精细瞄准、降灵敏度或视角缩放；250 ms 长按和 500 ms 连点窗口只影响发射，不能用于鼠标 X/Y 的延迟、平滑或去抖。已解锁的键鼠云台应能在不按右键、摩擦轮关闭时正常瞄准。

### 8.1 当前代码中直接影响手感的设置

下表是当前源码设置，不代表推荐最终值。实际构建若有其他配置覆盖，以构建结果为准。

| 项目 | 当前设置 | 对手感的影响及后续处理 |
| --- | --- | --- |
| 鼠标比例 | `mouse_yaw_scale = mouse_pitch_scale = 0.002` | 在映射器中乘原始值后夹到 `[-1, 1]`，输入绝对值达到 500 就饱和；它目前不是独立的 rad/count 灵敏度 |
| 云台命令限速 | Yaw `1 rad/s`，Pitch `0.8 rad/s` | 约 57.3°/s、45.8°/s；加大鼠标比例可能只会更早碰到限速 |
| 位置环死区 | Yaw `0.012 rad`，Pitch `0.01 rad` | 约 0.69°、0.57°；当前 PID 将死区内误差置零，可能使微调呈台阶感，但不等于全部控制输出必然归零 |
| 速度参考升降斜率 | Yaw `20 rad/s²`，Pitch `8 rad/s²` | 限制速度参考变化；仅从零升到上述命令限速就分别需约 50、100 ms，不含反馈动态 |
| 速度反馈滤波 | Yaw `0 s`，Pitch `0.02 s` | Pitch 有 20 ms 时间常数的低通滤波，会影响相位和响应；它不是固定延迟 20 ms 的缓存 |
| 速度误差软死区 | Yaw `0`，Pitch `0.02 rad/s` | Pitch 内环还会削弱小速度误差，应与位置死区分别分析 |
| 命令与执行调度 | 仲裁周期默认 10 ms；样例每轮末尾休眠 5 ms | 加上本轮计算、日志及调度开销才是实际周期，不能直接认定执行频率恒定为 200 Hz |
| 小 Yaw 行程 | `(7340 - 5770) / 8192 × 360° ≈ 69°` | 当前小云台不能单独完成 180°/360°转向；大幅转头需要大 Yaw 协同 |

修改入口：[鼠标映射参数](../../include/robotics/command/manual_command_mapper.hpp)、[命令映射](../../lib/robotics/command.cpp)、[云台控制配置](../../samples/robotics/command_gimbal/src/board_config.hpp)、[机械标定](../../include/robotics/vehicle/calibration.hpp)、[仲裁周期配置](../../lib/Kconfig)、[执行循环](../../samples/robotics/common/shooter_bench.hpp)。

### 8.2 先确定鼠标值是增量还是速度

官方 DT7/DR16 手册将 X/Y 字段描述为移动速度，并给出名义 14 ms 一帧。它没有证明当前 PC 客户端送出的数值就是未缩放的鼠标硬件 counts；本地 `RemoteMouse` 的“位移”注释也不能代替实际链路确认。[官方手册，第 5–7 页](https://rm-static.djicdn.com/tem/4.RoboMaster%20%E6%9C%BA%E5%99%A8%E4%BA%BA%E4%B8%93%E7%94%A8%E9%81%A5%E6%8E%A7%E5%99%A8%EF%BC%88%E6%8E%A5%E6%94%B6%E6%9C%BA%EF%BC%89%E7%94%A8%E6%88%B7%E5%86%8C.pdf)

先在电机不输出时记录：原始 `mouse.x/y`、原始帧序号、接收时间戳和帧间隔。固定 DPI 与 PC 软件配置，在鼠标垫上标出一小段距离，分别慢移、快移、停止、反向，观察零值是否及时到达、数据有无裁剪、每次移动的累计量是否一致。若能读取客户端实现，同时确认它使用的是事件增量、采样平均速度还是经过其他缩放的数值；固定帧率下仅凭波形可能无法唯一判定单位。

按明确的数据合同选择一种处理方式：

| 实际输入合同 | 建议映射 | 时间处理 |
| --- | --- | --- |
| 每帧运动增量 `Δc` | `θ_goal += sign × k × Δc`，`k` 单位 rad/输入单位 | 每个原始帧只加一次，不再乘控制周期 `dt` |
| 已标定速度量 `m` | `ω_request = sign × k_v × m`，再由云台积分角速度 | 每个有效控制周期使用真实 `dt` 积分一次；`k_v` 单位为 (rad/s)/输入单位 |

增量型输入需要在原始成功解码处保留完整帧或累积总量，消费者按序号/会话求差，不能只取最后一帧而漏掉中间增量。速度型输入可以在有效期内保持上次速度值；重复读取同一速度快照本身不等于重复消费增量，但不能每次读取都重新积分一整个输入采样周期。

现有 `GimbalAxis` 在 `Rate` 模式中已执行 `rate × dt`，不要在上游又乘一遍 `dt`。如果上游已经累积成角度目标，应使用相应角度通路并明确参考坐标，不要再把角度当角速度传入。

失联、会话切换和时钟异常时清除输入历史及过期运动请求；恢复后按明确的有效反馈重新建立目标，不追补失联期间的鼠标运动。数值限位、目标参考重建和故障处理不能依赖鼠标缓存读取得到“新时间戳”。

### 8.3 用固定比例建立基础灵敏度

先固定鼠标 DPI、客户端灵敏度、显示缩放和摄像机视场角，默认采用线性映射，不叠加鼠标加速度曲线。若 PC 端允许选择原始鼠标输入，优先用未经过桌面缩放/加速度的通路；这有利于视角控制，但必须确认透传客户端是否实际使用该通路，MCU 端无法凭配置撤销已经发生的非线性变换。[GLFW 原始鼠标输入说明](https://www.glfw.org/docs/latest/input#raw_mouse_motion)

对于确认是真实 counts 的增量输入，可用游戏中常见的“移动多少厘米转一圈”表达灵敏度。设 DPI 为 `D`，期望 `L` 厘米对应 360°，则：

```text
k = 2π × 2.54 / (D × L)       // rad/count
```

例如 `D = 800`、`L = 40 cm`，得到约 `0.000499 rad/count`，理想情况下移动 2 cm 对应 18°。这是数学换算示例，不是建议直接给当前云台设定的数值。当前小 Yaw 行程有限，只在限位内的小角度范围校准，不实际尝试转一整圈。

如果透传值已经缩放，就用“实际输入累计量对应多少角度”标定等效比例，不直接套 DPI 公式。对速度型输入标定 `k_v` 后，同样观察实际移动距离与最终转角的关系。Yaw/Pitch 的符号分别确认，不能通过调负 PID 来纠正鼠标方向。

未来参数应将“输入灵敏度”和“机构速度上限”分开。现有映射近似为：

```text
ω = clamp(-mouse × mouse_scale, -1, 1) × max_rate
```

因此修改 `max_rate` 会同时改变未饱和区的灵敏度。建议在单位明确后改成“先按独立灵敏度生成角度/角速度，再按机构能力限幅”，避免调转头上限时连微调比例一起改变。

先在固定视场角下调好；不同视场角会改变相同转角在画面上的视觉位移，后续有变焦时再独立标定缩放倍率，不能通过右键摩擦开关偷偷改变比例。

### 8.4 微调、滤波与控制环怎么调

按“输入语义正确 → 速度内环 → 位置外环 → 操作灵敏度”的依赖顺序处理。这里的内环是跟踪电机转速的环，外环是根据位置误差给内环速度目标的环。参数调整在后续无弹人工调参阶段进行，不在本次文档编辑中执行。

1. **先观察噪声和机构摩擦。** 鼠标不动时记录输入是否为零、编码器/陀螺是否抖动、输出是否周期振荡；检查机械间隙和阻力。输入不为零与电机自己振荡是两类问题，不能用一个大死区一起掩盖。
2. **再处理速度内环。** 在已确认的速度、电流/力矩范围内观察小速度指令的跟踪、停转和反向。持续饱和而速度上不去时先定位限幅或负载，不继续提高位置增益。积分用于补偿持续偏差，不能无限增加来“加快响应”；保留积分限幅与既有保护。
3. **然后缩小位置死区。** 当前约 0.69°/0.57°值得优先观察。根据反馈分辨率、静止噪声与机械间隙逐步减小，记录小目标变化能否形成实际运动及是否产生抖动；不要把死区直接清零当作通用答案。鼠标轴也不应直接套摇杆的 3% 回中死区。
4. **按噪声需要使用滤波。** 分清鼠标输入滤波、速度反馈滤波和 PID 微分滤波。当前 Pitch 的 `measurement_filter_tau_s` 作用于反馈，不是鼠标平滑；减少它可能改善跟踪相位，也可能放大噪声，必须结合波形决定。已有稳定控制器不要同时改变多处滤波与增益。
5. **最后调整速度斜率。** `reference_slew` 限制启动、停止和反向的速度参考变化；过小会拖，过大会要求机构承受更高加速度。分别记录停止拖尾与电流/力矩饱和，再按机械能力调整升、降斜率，不靠提高鼠标比例解决。

若需要对鼠标速度增加一阶低通，可使用有明确时间常数的形式，而不是固定长度、固定系数的多层平滑：

```text
alpha = dt / (tau + dt)
filtered += alpha × (input - filtered)
```

`dt` 对应滤波更新的真实时间步长，`tau` 是秒；`tau = 0` 表示直接通过。先不新增输入滤波，只有原始输入噪声确实影响控制时才引入小时间常数。该公式适用于速度/连续值；若滤波对象是每帧位移增量，需要额外保证总位移不被重复、遗漏或因裁掉滤波尾部而改变，不能照搬后就宣称距离比例不变。

### 8.5 快速甩动、停止拖尾和机械限位

快速移动时同时看“目标角”和“实际角”。如果目标已停止而实际角还在追赶，应定位位置误差积累、限速、斜率或输出饱和；如果目标本身仍在移动，应先查鼠标输入保持、滤波尾部和时间处理。

机械能力不足时，完整保留全部鼠标位移会产生追赶时间；限制追赶距离则会丢弃部分超出能力的输入。必须明确这项取舍，不能承诺任意速度下既完全保留转角又瞬间停止。

建议在未饱和范围保持固定比例，在快速甩动超出能力时限制目标领先实际姿态的角度，并记录限幅是否发生。限位轴上的示意处理是：

```text
candidate = 上一目标 + 本轮有效输入增量
candidate = clamp(candidate, mechanical_min, mechanical_max)
goal = clamp(candidate, measured_angle - max_lead_rad,
                        measured_angle + max_lead_rad)
goal = clamp(goal, mechanical_min, mechanical_max)
```

这只是限位轴的目标生成示意，不是可直接粘贴到所有云台模式的控制器。`measured_angle` 必须新鲜且与目标使用同一参考坐标；连续轴要处理角度环绕，惯性目标要处理坐标变换。`max_lead_rad` 应结合跟踪误差与可接受拖尾标定，过小会使机构被动带着目标走并削弱保持能力。

软限位处不要继续积累屏幕外的巨大目标；收到反向鼠标输入后应能及时离开限位。有限小 Yaw 的大角度转向应交给大 Yaw/底盘分配，在保持同一个瞄准目标的同时使小 Yaw 回到合适工作区间，不能直接放宽机械限位。

### 8.6 调度、惯性稳定与画面延迟

DR16 的输入节奏、仲裁线程和执行线程是不同的时钟节奏。提高控制频率可以改善输入到输出的处理等待和闭环更新，但不会把名义约 14 ms 的新输入变成 1 ms 一帧。先记录实际周期分布、最大间隔与输入年龄，再决定是否缩短当前 10 ms 仲裁休眠；同时观察共享 CAN 占用，避免只增加输出竞争。

周期内打印、大量遥测和阻塞发送可能带来抖动。保留采样时间戳，把遥测发送与控制分开，或使用不会阻塞控制的有界缓冲。不要把控制线程读到数据的时间当成鼠标实际动作发生时间。

当前 `gimbal_shared_can` 使用关节控制，车体运动时保持画面方向还需要接入已有 [惯性云台适配器](../../include/robotics/gimbal/inertial_gimbal.hpp) 和有效 IMU 数据。先确认安装变换、坐标方向及参考重置规则，再调稳定效果；否则固定台架上手感正常，上车后仍可能随车体摆动。

建议把延迟分成三段记录：

| 段落 | 观察量 | 用途 |
| --- | --- | --- |
| 输入接收 → 命令/总线输出 | MCU 同一单调时钟下的接收戳、命令戳、提交戳 | 判断软件排队和调度等待 |
| 命令 → 实际角度响应 | 目标角/速度、反馈角/速度、输出饱和 | 判断闭环和机械响应 |
| 真实运动 → 屏幕画面 | 同一外部录像中拍到机构与显示屏，或采用已同步的测量方式 | 判断摄像、编码、传输、显示延迟 |

没有时钟同步时，不直接用 PC 时间戳减 MCU 时间戳。仅凭接收戳也测不到“鼠标动作 → 无线接收”之前的延迟。画面延迟高时，操作员会因反馈滞后反复修正；不能通过提高 PID 或灵敏度消除图传延迟。

### 8.7 后续人工调参顺序与记录项

先保持摩擦轮关闭、无供弹，在机械行程内完成瞄准调参。控制链路实现完整并最终编译后，再由操作者按下表进行现场调参；本次没有运行这些动作。

| 顺序 | 人工操作 | 重点记录及预期 |
| --- | --- | --- |
| 1 | 固定 DPI/视场角，电机不输出，慢移和快移相同距离 | 原始值、帧间隔、累计量、零值与裁剪，明确输入合同 |
| 2 | 云台小幅正向/反向移动 | 方向正确、目标单位正确、参考与机械限位一致 |
| 3 | 低速微调与静止保持 | 输入已变化但目标不变时查映射；目标变化而实际不动时查死区/摩擦/内环 |
| 4 | 相同小距离分别慢移、较快移动 | 未限幅时最终目标转角接近；记录限幅标志，避免把饱和后的差异当灵敏度漂移 |
| 5 | 快移后停止，再迅速反向 | 目标领先量、实际停转时间、反向迟滞、输出饱和 |
| 6 | 分别观察 Yaw/Pitch，必要时接入惯性稳定 | 两轴响应差异、静止抖动与车体扰动，不要求盲目使用相同 PID |
| 7 | 接入操作画面，最后在无弹条件下加入摩擦轮运行 | 区分图传迟滞、摩擦振动和共享 CAN/电源影响 |

记录至少包括：原始帧序号与时间戳、X/Y、输入年龄、控制 `dt`、目标角、实际角、目标/实际速度、输出电流或力矩、各层限幅标志。现有发射遥测通道以拨盘为主，若增加云台数据，应明确通道含义，不把拨盘速度当成云台反馈。稀疏显示刷新不能代替控制周期级采样。

每次只调整一个明确原因对应的参数组，记下旧值、新值和操作条件；不要同时改 DPI、灵敏度、PID 和滤波后凭总体感觉猜原因。

### 8.8 现象与优先定位方向

| 现象 | 优先查看 | 调整方向 |
| --- | --- | --- |
| 小幅移动不动，积累后突然跳一下 | 鼠标量化/裁剪、位置死区、速度软死区、静摩擦 | 明确输入分辨率，按噪声与机械状态缩小死区 |
| 快移和慢移同样距离，转角差很多 | 输入单位、重复积分/丢帧、PC 加速、速度饱和 | 先修正单位和时间合同，再校准比例 |
| 慢移正常，快移明显转不动 | 多层速度上限、斜率限制、输出饱和 | 按机构能力协调限速，保留饱和记录 |
| 鼠标停了，目标还继续动 | 输入值保持、滤波尾部、旧帧重复累加 | 修正输入消费和失效处理，减少不必要平滑 |
| 目标停了，实际还追很久 | 目标领先量、位置环、减速斜率 | 限制目标积累，调整内外环与减速能力 |
| Pitch 比 Yaw 更黏 | 两轴斜率、反馈滤波、机械重力负载差异 | 分轴调参，先用数据解释差异 |
| 固定台架正常，上车后视角漂 | 关节控制与惯性参考、IMU 安装/时间戳 | 接入并标定惯性稳定和大 Yaw 协同 |
| 开摩擦轮后才抖或迟钝 | 机构振动、电源、总线/调度负载 | 分离机械、电气、通信因素，再决定是否调整滤波 |

本节新增实施涉及鼠标运动映射、长生命周期目标状态、云台配置和诊断数据；发射手势仍沿用前文已经确定的规则。建议先完成整条输入与目标链路，再做最终编译和上述现场调参，不能用调 PID 代替输入语义修正。
