## 当前配置里容易误判的事实

- `connections_confirmed=true`、`imu_mounting_confirmed=true`：确认门存在，但当前常量已放行。
- `require_referee_for_motion=false`、`require_power_budget=false`：正式手动入口当前不因裁判许可/功率预算缺失停车。
- 正式底盘 `Frame::Body`、`compensation_enabled=false`：151的双IMU初始航向配对门未用；大Yaw仍依赖两个真实gyro。
- `startup_heading_alignment_confirmed=false` 不会阻断当前Body平移；`big_yaw_native_velocity_profile_confirmed=true`、`big_yaw_heading_lock_enabled=false`，当前大Yaw走原生速度后端。
- 正式云台 `max_lead_rad=0`、`yaw_output_valid=pitch_output_valid=true`、`require_permission=false`：174、172、173不是当前运行门。
- 两个正式入口不实例化发射执行器、视觉接收器或外置头部IMU；相关可选链仍列出，但不能用它们解释当前手动入口不转。
- `RunState::Blocked` 标签本身不证明永久锁存；执行器部分Blocked可在后续输入变化后恢复。真正缺少运行内恢复路径的例子是053/054与074。
- 036、156、157、159是状态/诊断问题；158是调度；089、112、161是范围/标定说明。它们不都对应一条可删除的“拒绝运行if”。

## 决定填写格式

可以直接回复编号，例如：

```text
保留：……
删除：……
调参：016 → ……ms；130 → ……ms
解耦：105/108 → 单轮异常只影响该轮；113 → ……
未列出的：保持未定
```

如果希望“只列保留项，其余删除”，请同时说明范围是“正式运行拦截”还是也包括限幅、协议格式校验与可选路径；清单里的诊断、坐标变换和PID本体不会仅因编号未被列入保留而被误当成门控整体删除。
