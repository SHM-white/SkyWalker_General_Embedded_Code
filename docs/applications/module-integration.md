# 模块联动与调用路线

两个 sentry 应用由公共 vehicle_bench 调度。应用拥有物理 CAN、Motor、输入线程和统一发布者；控制器保存最新目标，执行器处理输入有效性，各轴的协议恢复由 Motor/CAN 工作线程完成。

| 层 | 职责 |
|---|---|
| Remote/Referee/Vision/IMU 来源 | 保留采样 stamp、实际质量和参考 |
| CommandManager | 注册来源，后台采样和仲裁 |
| 快照消费者 | 检查原输入年龄及业务许可，不改生产时间 |
| 运动学/惯性适配 | 数学坐标与各轴计算有效性 |
| Executor | 连续提交目标，明确启停和输入超时 |
| Motor/CanBus | 保存运行意图、限频清错/使能、独立自动恢复 |

各控制器一个执行写入线程，所有共享 DJI CAN 机构先暂存，统一 commit 一次。一路 CAN 恢复或一轴掉线不撤销 RC 输入，不停止其他机构的 update。没有 Group 故障传播或 RecoveryGate。

功率控制保留已启用预算和测量有效期，不再要求数据晚于某次电机恢复。云台数学输出按两轴测量有效性区分，IMU 坐标身份继续保留。Shooter 只迁移电机执行接口，热量、卡滞与离散事件业务规则沿用。

板间统一 v4，无 resume_generation。实际板重启/链路失效属于输入身份问题，Motor 恢复不改变板间上下文。BigYaw 目标发送不需要对端电机先 ready。

完整文件顺序、协议偏移与样例映射见[实施指南](../dev/电机持续指令与独立自动恢复重构实施指南.md)。
