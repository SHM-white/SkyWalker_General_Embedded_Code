# 双主控交互式架构文档

用“两块板、六步主流程”阅读 SkyWalker 架构，点击模块查看输入输出、接口约束、依赖和对应源码；支持正常控制、串口掉线、电机掉电恢复三种场景，以及搜索和实现状态筛选。

## 打开方式

- 在线入口：[架构浏览器](https://skywalker-architecture-browser.docile-raven-1977.chatgpt.site/)（私有部署，需要访问权限）。
- 本地入口：克隆仓库后用浏览器打开本目录的 `index.html`。四个网页文件必须放在同一目录，不能只下载 HTML。
- 也可以从仓库根目录运行：

  ```bash
  python3 -m http.server 4173 --bind 127.0.0.1 --directory docs/architecture-browser
  ```

  然后打开 <http://127.0.0.1:4173>，按 Ctrl+C 结束服务。

GitHub 文件页显示 HTML 源码，不执行网页交互。本目录是无构建步骤的静态网页，不依赖 npm、外部 CDN、后端或登录服务；本地阅读不要求在线入口的访问权限。

## 文件职责

| 文件 | 用途 |
|---|---|
| `index.html` | 双板总览、六步流程、详情和模块目录的页面结构 |
| `styles.css` | 布局、状态颜色、连线及移动端样式 |
| `data.js` | 代码基线、17 个模块、接口约束、依赖、源码路径和状态 |
| `app.js` | 中文输入输出说明、场景步骤、节点选择、搜索筛选和路径播放 |

这些文件是直接维护的源码，不是需要重新生成的构建产物。

## 维护流程

本次导入使用 `docs/architecture-browser` 分支与独立文档 PR。后续未合并的维护可继续提交到该分支；合并后建议从最新 `main` 新建 `docs/architecture-browser-<主题>` 分支，保持文档变更独立审阅。

1. 对照目标代码提交，核对双板应用接线、命令与安全接口、串口协议和电机层。先确认变化，再修改文字与状态。
2. 在 `data.js` 更新模块、约束、依赖和源码路径；在 `app.js` 同步输入输出说明、场景步骤与节点映射。新增模块时同时核对 HTML 中的按钮和模块数量。
3. 更新基线时，同时修改 `data.js` 的 `COMMIT`、`index.html` 页头链接与页脚短 SHA、本 README 的代码快照。源码链接应始终指向同一个完整提交。
4. 运行 `node --check docs/architecture-browser/data.js` 和 `node --check docs/architecture-browser/app.js`；用上述本地服务检查模块点击、源码链接、三种场景、逐步讲解、重置、搜索和筛选。
5. 检查桌面和手机宽度，无横向溢出；确认“已有代码”“待实机”“待实现”含义未混淆。
6. 提交 PR，说明修改依据的电控提交、变化模块和实际检查结果；文档修改无需构建或烧录固件。

## 源码公开与在线部署

本目录随公开仓库提供，任何人均可下载查看。网页中的标签不提供访问控制。

既有在线站点继续使用其独立的私有访问控制。本次导入不启用 GitHub Pages，也不增加自动部署。合并这个 PR **不会自动更新在线站点**；需要发布时，应将本目录的四个网页文件同步到既有站点的静态目录，保留站点原有访问设置，并核对实际部署版本。

公开目录不包含站点凭据、访问名单或托管配置。后续维护时也不要把这些内容提交到仓库。
