# 文档更新与代码同步清单

每次代码变更使用本页待办逐项更新。目录扫描只能自动发现 Markdown，无法判断 API 或运行语义是否正确。接口详情维护在 `docs/api/*.md`，在线浏览器直接读取这些文件；不再另写 JS 接口契约数组。

当前内容基线：`main@99a97c9`（2026-10-05）；浏览器导航与自动扫描是在该代码之上维护的文档功能。一次更新须记录实际核对的提交；文档提交或部署提交不应被误写成固件能力基线。

## 文档分工

| 位置 | 维护内容 | 何时更新 |
| --- | --- | --- |
| `docs/api/*.md` | 常用公开签名、参数、单位、返回、错误、时序、边界、示例、生命周期、源码链接 | 公开 API 或实际行为变化 |
| `docs/modules/**` | 模块概念、职责、算法 / 协议、配置和使用前提 | 模块行为或配置变化 |
| `docs/guides/**` | 跨模块初始化、周期调用、停止 / 恢复、排障和迁移 | 调用链、并发、时效或恢复改变 |
| `docs/applications/**` | 应用线程、设备装配、权限、数据来源与真实缺口 | 正式应用配置或接入改变 |
| `samples/**/README.md`、`tests/**/README.md` | 独立入口、构建指令、硬件前提和预期现象 | 样例 / 验证入口改变 |
| 根 `README.md`、`docs/README.md`、主题索引 | 推荐阅读路线、能力摘要、源码基线 | 大改动、迁移、新主题或能力变化 |
| `docs/dev/**` | 历史设计与待实施方案 | 新设计或需要注明实施状态；不用于现行 API 定义 |
| 浏览器 `data.js` | 模块 ID、分类、摘要、状态、依赖、Markdown 路径及关系图布局 | 模块增删、关系或接入状态变化 |
| `architecture-data.js`、`vehicle-diagram.js` | 当前 / 目标架构、缺口、调用链、主图、源码基线 | 实际装配或工程目标变化 |
| `workspace_docs.py`、`run.sh`、部署 workflow | 扫描规则、本地服务与静态索引生成 | 文档组织规则或发布方式变化 |

## 每次更新待办

### 1. 确定实际代码基线

- [ ] 获取最新目标分支，记录 branch、完整 commit 和核对日期。
- [ ] 按源码变更范围列出受影响模块、应用、协议、样例和文档。
- [ ] 分清已实现、待装配、待测量和设计目标；文档不能从代码存在推断实机完成。
- [ ] 大改动先调整阅读路线和内容归属，列出旧 API 到新调用方式的迁移表。

### 2. 更新接口与主题正文

- [ ] 对照公开头文件和实现更新 `docs/api` 的签名、参数、单位、返回及错误；记录等待状态与非法调用的区别。
- [ ] 更新生命周期、线程 / 中断、写入者所有权、时间戳、代次、默认值及资源限制。
- [ ] 示例保留构造 / 初始化前提，区分可直接构建的工程与说明性周期片段。
- [ ] 更新模块概念、协议编码和配置前提；公共规则放公共主题页，型号页链接引用。
- [ ] 删除旧接口调用；历史记录标为历史 / 待实施，不能作为当前主入口。

### 3. 更新跨模块行为与应用

- [ ] 更新初始化、update / setter → commit、停止、掉线恢复和多轴 / 多 CAN 的结果处理。
- [ ] 更新输入生产年龄、命令序号、boot / link、板间 wire version 与双方升级要求。
- [ ] 更新实际应用装配、默认阻断、真实测量来源、观测有效位和硬件未验收项。
- [ ] 更新样例 / 测试 README、排障与迁移说明；不把软件目标或统计当作实测反馈。

### 4. 更新导航与在线图

- [ ] 更新根文档中心、API 分类和主题阅读顺序；普通新增 / 删除 / 改名 Markdown 不需要手写目录数组。
- [ ] 新逻辑模块在 `data.js` 添加摘要、稳定 ID、`reference`、依赖和关系图布局；接口详细内容只写 Markdown。
- [ ] 应用接入变化同步 `architecture-data.js`、`vehicle-diagram.js` 与当前 / 目标链路。
- [ ] 更新源码基线及缓存版本；基线日期和提交在首页、文档中心、接口参考及图中保持一致。

### 5. 验证、PR 与发布

- [ ] 按本次任务授权和仓库检查规则完成适用语法 / 构建 / 运行验证，并记录实际结果；未执行的验证明确写出。
- [ ] 需要浏览器验收时核对模块 Markdown、目录刷新、搜索、源码 / 正文链接、主图与小屏导航。
- [ ] 需要硬件验收时使用对应样例，记录板卡、接线、模式、参数和实际停止 / 重接现象；文档本身不替代验收。
- [ ] PR 写明核对基线、行为变化、受影响文档、验证范围、未完成项和发布方式。
- [ ] GitHub Pages 从部署树自动生成 `docs-index.json`；其他静态发布同样运行扫描器，打包包含索引与原始 Markdown。
- [ ] 更新现有在线站点并确认部署状态；保持既定访问范围；记录部署提交和源码能力基线分别对应什么。

本地阅读 Markdown 不需要服务器。使用浏览器时运行 `bash docs/architecture-browser/run.sh`；动态扫描包含未提交文件。静态站点只展示已部署快照，新增内容在下一次部署出现。启动及静态生成命令见[浏览器说明](architecture-browser/README.md#自动发现-markdown)。
